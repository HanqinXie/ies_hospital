# 医院综合能源系统研究模型 V19

本仓库保存医院电、热、冷综合能源系统的 **M19 聚合准稳态模型**、执行感知调度策略及其冻结研究结果。模型以既有 DOE/IDF/8760 小时需求和设备参数为基础，分别记录命令生成、队列到达、持久许可、实际执行、保护和服务恢复；不使用 MPC，也不向策略提供未来故障、修复或停电结束时间。

方法、参数来源和假设见 [模型说明](docs/v19/PAPER_MODEL_SPECIFICATION.md)，仓库资源补齐及复现步骤见 [复现指南](docs/REPOSITORY_REPRODUCTION.md)。

## 场景与策略

论文类别采用下列定义。旧代码的 native 标签保留作兼容，不能直接按旧标签解释论文结果。

| 类别 | 定义 |
|---|---|
| L1：单设备故障 | 一个设备或接口失效/降额，关闭继发传播作对照。 |
| L2：故障连锁 | 与配对 L1 保持相同故障靶和事件时钟，允许已登记的应力代理触发继发保护；L2 标签不等于实际发生了跳机。 |
| L3：无故障需求突增 | 电、热、冷或混合需求冲击，没有初始设备故障。 |
| L4：需求突增叠加故障 | 外生故障与需求冲击共同作用，保留各自事件时钟。 |

四种策略共享 M19 物理模型、动作权限、执行队列和服务判据：

| 策略 | 登记身份 | 主要区别 |
|---|---|---|
| E | `endurance_restore_p0_ready_v14r6` | 沿用续航、恢复和关键服务准备偏好。 |
| K1 | `readiness_handoff_K1_v15` | 考虑命令已到达而机组尚未就绪时的服务交接与准备。 |
| C19 | `C19_critical_reserve_v19r1` | 根据当前关键需求和剩余 DG 轴功预算，加入关键能源预留偏好及相应目标重排。 |
| C18/M19 兼容版 | `C18_service_rich_M19compat` | 接受共同接点与回切接口适配，关闭 C19 的关键能源预留，保留原偏重一般服务的相对次序；不是旧 C18/M18 的字节不变复现。 |

P0–P3 是模型中的服务优先级。主动切除、已连接少供和实际交付分别评价；电、热、冷 ENS 分列，不直接相加解释为医疗损害。

## 先检查资源，再运行

在仓库根目录、已准备好 Python 依赖和求解器的环境中执行：

```powershell
python scripts/repository_assets.py verify
```

仓库保留继承代码、历史小型配置和数学回归 fixture 的原路径，但**不上传11篇文献PDF及3份来源PDF/XLSX原件**。严格冻结复现要求原 66 项输入的字节及 SHA 全部一致，因此新克隆不自动等于完整复现环境。若检查报告缺少外部资料，可从已有的完整原项目目录按登记清单补齐，再检查：

```powershell
python scripts/repository_assets.py restore --source-root "D:\path\to\code_4_2"
python scripts/repository_assets.py verify --require-full
python scripts/test_v19.py
```

`restore` 的来源目录应包含哈希一致的原资料，不能用同名不同版本文件替代。文献及设备/排放资料的来源、版次和 SHA 见复现指南与参数登记。实际模型注册、运行和结果复核步骤以 [复现指南](docs/REPOSITORY_REPRODUCTION.md) 为准；不能通过省略输入清单、修改冻结绑定或扩大容差来宣称同版本复现。

求解器及可用的 Gurobi 许可是外部运行条件；仓库和 GitHub CI 不提供或保证该许可。

- 冻结后的 **406 条最终轨迹**包括 310 条比较轨迹和 96 条确认轨迹，均完整结束且单轨迹审计通过。完整结束不等于服务零中断。
- 本轮 V19 跨开发源码版本的登记共 **506 条**：实际启动 466 条，其中 465 条完整完成、1 条旧 native 求解失败；另有 40 条未开始。失败与未开始记录保留，不能写成“506 条全部通过”。
- 主 80 规格属于已见回归；冻结后的八背景确认单列，仍来自同一医院模型与年度数据支持。原最终 12 背景保持封存。

结果存在实际取舍：八背景确认没有显示 C19 相对 E/K1 的 P0 优势；主面板 C19 的条件 CO₂ 高于 E，72 h 正常窗费用也高于 E。DG 排放采用代表油耗的条件映射，真实启动、空载和低载油耗仍有未知；这里的 CO₂ 评价不是完整生命周期 CO₂e。详见 [收尾报告](docs/v19/V19_MODEL_CLOSEOUT_REPORT.md) 与 [排放方法](docs/v19/EMISSIONS_METHOD.md)。

## 适用边界

这是设备转换、有限执行时钟和服务后果的研究模型，缺少真实配电潮流、厂家暂态与继电保护校准、完整医院支路拓扑和临床后果验证。共塔故障、初始启动、有限能源及正接点延迟仍可能造成缺供。条件静态准备检查不证明连续转供路径或未来持续供能；仿真未越温度阈值也不能替代缺冷评价。本仓库不提供现场、临床或全场景供能保障结论。

源码位于 `src/`、`tools/`，测试位于 `tests/`，参数位于 `configs/`。V19 依赖跨代继承链，不能只复制 `tools/model_closeout/`；`bootstrap_planners.py` 是历史一次性迁移工具，不是运行入口，不应重新执行。后续升级应另建版本并重新登记、测试和冻结，保留 V19 的输入、失败证据及原结果。
