# 固定运行设定、严格无优化U的后续执行任务书

状态：设计任务书；forward尚未实现，禁止据此生成或发布baseline曲线。本轮无科研运行授权。

## 目的与固定主规则

从同一合法故障前连续状态出发，t60起不调用上层、下层、保护探测或评价见证中的任何调度优化器。只维持故障前最后实际运行参考、按原时延到达的既有命令以及已存在的非优化自动切换和保护。负荷、容量、优先级、库存和设备状态保持原定义。规则一次登记，以物理可执行性为依据，不按结果变差或变好调整。

许可上限与运行参考必须分开：ABS/每台EC/Grid/DG的已到达ceiling不得自动当成新的可任选出力；必须另外保存最后实际运行参考。故障可以使实际交付降低；不能在没有已发运行目标的情况下，因其有剩余许可就提高备用冷机的参考出力。到达的旧命令按原有队列/覆盖规则处理，不能假装未到达，也不能免除启动/爬坡/供电依赖。

## 建议分解与完成顺序

1. **契约和快照。** 新版本目录与model_id保存t60前最后实际端口值、各设备目标/permission、排队命令、GT时钟/爬坡锚点、DG机械和燃料状态、锅炉连续供电复位状态、储能状态及联锁。不得从未来N/R轨迹借值。所有规则和版本写入绑定。
2. **纯算术实际流评估器。** 接收当前状态、当前负荷/故障、已到达目标和区间长度；返回实际端口流、served/lost、辅助用电、蒸汽弃置、冷却塔排热、费用及残差。不得调用LP/MILP/NLP、优化型投影、按ENS/成本排序的候选枚举；零目标可行性优化也不合格。仅允许固定规则算术、物理方程求解及事件求根，且不得用其寻找最优分配。
3. **先完成可唯一闭合的组件。** 沿用`ContinuousLossStore.project_energy/boundary_hours/commit`、柴油机械preview/commit、GT时钟和`limited_down_endpoint`、锅炉RestartState、温度/失效积分。确定量必须由同一实际端口流积分，不能用许可上限积分。空/满库存和燃料耗尽必须定位真实边界并切分区间。
4. **显式资源不足规则。** 固定运行参考允许因硬容量、可用性、已存在保护和能源不足下降，不能因比较候选而增加。服务仍按原P0→P3顺序；同优先级内固定、可复现的分配规则必须逐项写入契约，不得宣称实现了原优化目标的最优性。蒸汽对建筑供热/ABS、供电对建筑/冷机/锅炉启动、冷却塔对ABS/EC的竞争需要明确的执行关系；先写合成反例再实现，不能用“总量min”跨过依赖耦合。
5. **替换优化性保护见证。** 保留原阈值、时钟和强制跳闸能力，但minimum-floor子集择优、最大辅助负荷LP、rearm/release可行性优化须由预定执行状态机和实际流算术替换。无法证明合法重启则明确保持既有锁存，不制造故障，不新增自动重启权限。不能把旧优化探测包装成传感器。
6. **最小公共事件推进核。** 单一实现任务串行处理：到期故障/旧命令→执行器可达性→纯forward流→保护/库存事件分段→状态与账本提交。禁止在一次试算中提交库存或时钟；只有最终实际区间可提交。无法闭合时保留完整输入、原因和未完成前缀，fail-closed；不可填零、静默丢事故或宣布服务冻结后仍通过。
7. **证据接口。** forward结果应明确无优化来源；不得伪造solver_backend_layers或旧“已完成求解会话”。账本/独立审计器应直接重算真实端口和库存收支。下游要求旧求解证明的接口须有新模式迁移记录，不能制造优化证据骗过旧验收。

## 不可跳过的具体规则缺口

当前源码没有一个已实现、满足以上约束的唯一映射。后续实现必须在代码/登记表中具体化：

- 各converter reference随“已发但稍后到达的ceiling命令”怎样改变；ceiling本身不能等于实际目标。
- 供电不足时各实际端口如何逐层失电，蒸汽/冷却塔限额如何作用在固定converter参考上，以及建筑分级服务如何与辅机供电闭合。
- 原有Grid调节器、DG/ATS、UPS和冷储能自动动作中，哪些是既有固定控制，哪些实际上依赖旧优化器选择；后者必须重建固定规则，不能以“原有自动响应”名义保留。
- 保护残余应力如何由未优化的真实连接需求、实际供能和辅助请求计算；保持原代理适用边界，不把总缺供机械分摊为设备真实过载。

这些是待完成的实现依赖，不是本轮已实现的能力，也不要求用户再授权一次普通实现选择。若单个规则无法与现有物理边界同时成立，应明确提交反例和未完成范围，不凭空加拓扑或厂家参数。
