医院综合能源系统 V28 独立审查
日期：2026-10-27（北京时间）
审查对象：HOSPITAL_IES_V28_REVIEW_under100MB.zip
目的：判断模型是否正确、还需完善什么，以及如何有限收口。暂不写论文、不画结果图。

一、结论先行

V28 已经完成上一轮的两项主要修正：固定非辅机直接用电、让建筑辅机增量真实进入总需求；用达到原普通热水目标所需的有用热替代原实际交付曲线，并清楚区分独立本地热源与中央能源站。

本次对源码、六条 A 实际轨迹、五条 B 实际轨迹和年度最小原生数据独立复算，未发现需要推翻这两项修正或重做公共供能核心的重要错误。它已经具备作为“给定原型医院与设备条件下的故障供能调度模型”的基础。[E1–E4]

下一步的重心应从反复追查来源细枝末节，转到“采用同一新版需求的研究模型定版与机制验证”：真正验证外网退出后的接替、共用设施故障的多路径影响、无硬件故障的需求增长、以及需求与故障叠加时的保障和失效边界。

普通目标热水和 D/A/E 边界可以收口。源水罐 Cp 缓存、被替代的完整源水环路、本地高温热水动态及所有年度 warning 清零，不应继续作为当前中央 IES 定版的前置条件。

这不是宣称真实医院每个房间、每个用水点都已获得验证。当前采用的服务分组、负荷来源、辅机比例和设备模型有明确适用范围；在该范围内形成一版正确、可解释、有限验证的工程模型是可行的目标。

三、已经修好的部分

3.1 冷需求增加不再挤掉直接用电

独立确认新的公共关系为：
直接请求 = 源直接基准 + 明确的直接需求冲击；
建筑总电请求 = 直接请求 + 建筑辅机请求。

冷扰动不改直接基准；临床冲击只叠加一次；计划、可见状态、执行和服务核算采用同一口径。切除部分服务或失去辅机时，原请求仍保留，减少的辅机电不会变成新的直接电需求，也不会把原缺口抹掉。源风机组件的故障份额和厂站计电边界保持一致。[E2]

直接电请求变化/kWh                0                  约0（浮点舍入）
实际购电增加/kWh                 45.944247          45.997562

额外购电包括建筑辅机和原有站内制冷转换电。两种方式的正常原冷费用也与 V27 基线相符。原始直接电 ENS 增量约 0.000158 kWh 被保留，没有把 15.35 kWh 需求增量误叫作失供。[E2]

因此，这项工作不是改了标签，而是真正改变了需求和实际能源账。下一轮无需继续重构这一公共关系。

3.2 辅机故障不会再通过缩小需求“消失”

热循环泵可用率为 0.5 的实际例中，原热请求没有随故障缩小；60–120 分钟出现关键热服务中断，热 ENS 为 73.535403 kWh，其中 P0/P1/P3 约为 17.977634/18.171671/37.386098 kWh。120 分钟实际供热恢复，按既有确认规则于 121 分钟确认。[E2]

这说明模型可以保留并报告不利结果。供能不成功本身不等于计算失败。

同时，该结果来自已声明的泵—热服务比例近似及后续切除，90–120 分钟另有 P3 服务切除。它不是实测水力定律，不能据此反推出真实水泵少耗多少瓦会造成多少热量损失。现阶段保留工程代理即可，只有未来要做水泵选型、流量或扬程预测时才需扩展。

3.3 普通热水请求已经正式修正

源模型与新增观察 IDF 的独立比较表明：仅追加 694 个 Output:Variable，物理对象没有改变。提交记录显示实际年度观察完成，原四张 CSV 用原提取器逐字节重现。本次没有直接重读未随包提供的大 SQL，而是核对重导身份记录及保存的原生数组。[E3]

实际接受区间共 53,912 段，时长分别为 120/150/200/300/600 秒，合计完整一年。30 个末端的请求排程、流量和倍率与原生记录相符，使用同构建的水物性定义，没有直接使用上一轮的粗略估算。[E3]

有符号目标差：3,102.062322 kWh/年。

新普通热水不再驱动额外空气风机，但仍受热源、供电和循环泵约束。当前仍是 P3 中的聚合有用热服务，未建立30个取水点的温度动态或科室热水优先级。这个范围可以用于当前调度研究，不必因此再做一套完整管网。

故障前 GT2 确实在供能，前30分钟发电约62.3323 kWh。F/FD 在30分钟失去它，电网与其他机组接替。GT3 在75–85分钟实际付出1.666667 kWh启动电，85分钟后才发电。90分钟恢复的是GT2可用性，直到180分钟它仍未重新发电；这不应被写成90分钟实际接替供能。[E4]

这些过程及能量账通过独立复算。故障前物理和求解数值内容相同，原生记录中的求解耗时与剩余时间限制不同，因此不能声称完整文件逐字节一致。原热正常对照的策略身份包含输入版本而不同，但运行规则配置相同。初次过严比对及差异记录随本审查保留。[E4]

主要使用限制是：
— F/FD 中 EC1 已达到容量上限150分钟；FD购电达到850kW上限7.5分钟。供能成功并不代表各通路都有很大余量。
— 所有这些 B 案都保留外网；H0 没有安装 UPS 或蓄冷，柴油2400kWh轴功预算也未消耗。不能将其作为新版停电自持与库存耗尽验证。
— 故障后条件排放下降，来自既定排放因子和供给替换，不能推广为故障本身有减排收益。
— 没有关键中断时，恢复时间应为“不适用”；原始小额电缺口仍保留。

五、剩下真正值得完善的三项工作

5.1 在同一采用版本下完成四类情景的有限机制验收

N/F/D/FD 是正常、故障、需求、叠加的配对设计，能够分辨事件影响；它不自动等于整个研究的 L1–L4 已经覆盖完整。

当前 F 是 GT2 退出，HRSG2 本体仍健康但失去热源。这是有效的功能依赖影响。原始事件中没有二次保护跳闸或额外设备损坏，因此不能再给它增加未经发生的保护传播含义。[E4]

该功能传播有实际量值：30分钟时，正常/故障分支总余热蒸汽约2325.006/1162.503 lb/h，吸收制冷346.275/136.616 kW，电制冷544.540/754.199 kW，购电596.061/758.284 kW。已经出现“燃机退出→余热减少→吸收制冷下降→电制冷与购电接替”。因此不能说L2完全没做；需要补的是采用版中其他重要路径及外网中断的覆盖。[E4]

建议下一轮采用明确的工程分类：
L1：一个局部设备/供给故障及其接替；
L2：一个共用设施或上游故障，沿已建依赖关系影响多个下游供能通路或服务；
L3：没有外生硬件故障的医疗需求增长；
L4：既有故障与医疗需求增长叠加。

功能传播是可研究的范围，并不必须伴随第二台设备永久损坏。硬件故障、功能受限、保护退出、预设的第二个外生事件分别记账。不能把“按脚本过一会再关另一台设备”自动当成内生传播。

目前 research_stress_proxy=false；该已退出使用的过载请求代理可能在真实GT出力未过额定时触发，不能为了凑L2重新打开，并称为真实电过流。优先复用现有共用冷却塔/泵路径，验证可用率如何传递到EC/ABS能力及各级服务。[E4]

5.2 验证新版需求下的停电接替与有限库存

这比继续追加同一个有电网的短窗更有价值。应使用已有供电中断例，观察外网退出后：原已运行机组能供多少、备用机何时真正出力、启动和厂站辅机由谁供电、关键需求是否中断、存量如何减少、外网回归怎样恢复。

H0 与已登记 H1/H2 要分开。旧 four_L1_grid_winter 使用 H1 的40kWh UPS，不能迁移案例时把它当作H0已有设备。若复用H1/H2，保留原容量、初始库存和额定功率，明确它是另外一种已有硬件方案。无需重新做容量优化或凭空增加储能。[E4]

若已有同版本轨迹、组件检查确实覆盖某机制就复用。没有实际正出力或库存消耗的设备，不能仅凭配置中存在便算作通过验证。

5.3 固定来源与服务范围，避免下一轮重新混用口径

给源冷的25个受限小时加质量标记；新研究窗口与其求交，保留标记及解释，不静默删除。当前A/B窗口都不与其重叠。[E3、E5]

统一每个结果中直接电、建筑辅机、中央热冷服务、本地参考能耗、未知上游源之间的边界。若全部保留V28已选择的研究范围，可以直接推进机制验证；无需为“全院所有能耗”这个更大命题强行扩充当前模型。

六、哪些限制可以保留，不应继续阻止定版

6.1 Laundry 与 Booster 上游

Laundry保留本地燃气设备；Booster保留本地电加热，年电量7,334.001082kWh逐小时与原WaterSystems电边界一致，确认没有重复计入。两者是来源台账，不是另一次实测的故障供能过程。[E3]

Booster的60℃上游预热义务约12,941.798764kWh/年，源模型没有物理连接证据。V28选择不把它纳入中央高温保障，来源能源、费用、排放是null。这个选择符合上一轮授权；它没有被冒充免费热源。

只有以后要声称完整全院总能耗或全部高温热水保障，才必须接上可追溯的上游源并核算。当前正式指标应称本研究能源站范围内的服务、能源费与条件排放，不能把未知项当0后改称全院总量。

6.2 源罐储能与完整原水环路

源罐各项能量与燃料效率能够重算；年度native净热与连续热容端点势函数仍有离散路径差，完整原水环路缺库存/焓流。报告保留了残差，没有伪造配平。[E3]

中央IES并未把这些残差当作可用库存或免费热源，普通目标热也不依赖残差填补。因此，它们不是已证明的中央调度能量漏洞。本轮可以停止追查；未来若将原罐或原管网变成调度对象，再按实际用途补模型。

6.3 源冷9.5 zone·h

55区原生记录中，厨房9.333333 zone·h、放射科0.166667 zone·h，合计26条区—小时记录、25个唯一标准小时。它描述局部区域温度偏离冷却设定点的累计时间，不是全院停冷9.5小时。[E3、R2]

当前全部主试验窗口与这些小时不重叠，暂无证据由此推翻V28对照。全年冷输入仍应称源模型盘管交付代理，不能升级为完整真实需求。以后选中受影响窗口且这会改变结论时，再对厨房盘管/风量/水量或对应供水控制做定点诊断；不要默认新跑全年EP、放大冷量或重启温度拟合。

6.4 SQL完成标志及其他记录问题

原/新SQL的完成标志是TEXT FALSE，与结束日志及实际退出码不一致。项目已排除读取时误转bool，具体引擎原因未解。本次确认保存的全年时钟和核心原生量可复算。可以保留该冲突说明，不必把它变成下一轮主要开发任务。

七、建议如何收口

下一轮建议名为 V29“同版本机制验收与模型定版”，不要再新增一套泛化的审计框架。

保留V28核心和正式需求；先列已有证据，再补最少的缺口：同版本供热循环泵故障、实际停电接替、共用设施多路径传播；L3/L4优先复用当前有效证据，必要时补一例含受限资源的匹配组合。通常新增约6–10条轨迹足够，按确切风险决定，不凑数、不强制全部成功、不扩为季节×设备×策略全排列。

验收重点为：需求不随故障缩小，失去功能的路径真实传递，启动完成前不出力，辅助供电和库存真实支付，资源不足形成可解释的缺供，设备恢复可用与实际服务恢复分开，费用和排放来自实际过程。

如果这些机制在同一采用版本下通过，且没有守恒、需求重复/漏计、提前出力、库存透支或未来信息问题，可以将研究范围内的模型正式定版。模型可以报告某些工况保不住全部服务；这往往是资源与约束的真实结果，而非必须继续调参消灭的“错误”。
