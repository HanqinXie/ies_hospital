# 本轮新增研究边界

1. 正常源功能支持以实际GRID接触、正进口、聚合非UPS源及电平衡收据为条件。这不是GT控制DC或DG充电器接线/容量证明；控制电能、充电电能、Ah/CCA始终unknown，不记0。上一段证明不自动覆盖下一实际区间。
2. 原1440分钟是有限功能资格，未标定为电池续航。新主情景累计实际无正常源时间，正常源支持期间不消耗；没有自动补满或按日期恢复。None分支始终无恢复。
3. 连续正常源30/60/120分钟后重新取得资格是另行命名的功能假设。只有实际结算达到条件且有已消耗资格才恢复，不使用未来修复时刻，不承诺真实电池充电完成。启动次数终身总数与每资格周期余次分开。
4. DG_START_DC仅门控开始/尚未完成的启动；已READY/CONNECTED DG继续运行由原DIESEL硬件、轴功库存、rotor及接触器/保护控制。DG持续控制电源缺本机资料，属于单独研究边界。
5. 主运行无外部柴油补给。原库存是kWh轴功等效预算，不是升或化学燃料。当前不编造供油物流、燃油发热值或补给价格；不足可造成服务中断，不能自动回满。UPS和蓄冷仅按原实际功率、效率和损失补充。
6. 新准备规则只提出普通排队请求。保持至少一台当前健康GT的合法最低稳定出力请求，不等于任意单源故障后仍有在线备用。锅炉上限仍非瞬时热备用；没有真实暖机曲线。连续冷储目标60分钟可超过容量，缺口明确报告。
7. 原OPEN0.25分钟、锅炉电气再资格1/5/15分钟及全部物理参数不变。新OPEN前复核若受有限源期限限制仍可有损回退，不用控制标志代替供能成功。
8. H0/H1/H2分别为全年固定资源配置，不组合、不按事故切换设备。塔1%/2小时最乐观满库存必要冷缺口37.5545787868kWh仍只在登记静态排热包络成立，不称真实天气设备无解。
9. 服务阈值和60秒热/冷恢复确认沿用原V23指标。分块记录本身不重新定义material；全局指标由保存的实际service ledger小投影交原函数计算，不将其用于native-primal蒸汽核验。
10. 原完整输入和12个封存日不变；最长连续7天，完整源支持含初始化与终点额外源小时。未标为独立医院、跨年、年可靠率或临床环境验证。所有未观察尾段仍未知。

新迁移：`ContinuousStationState`只在原V28完整初始化快照完成后接入，初始锅炉状态不改。原正常核心、输入及已有producer仍由旧工作区保留。新界面只在新版本调用，旧reset/step接口不改。新分块写出在决策边界保留全部真实段、完整合法决策历史及全部队列/库存，不重置观察索引；只清空已持久化的求解日志。原日志类与每块sidecar保持，局部调用索引须与block ID/全局offset合用。普通日志计数/hash不用于物理状态等价判定。完整服务历史的内存随运行时长增长，不能声称内存恒定；长运行前须实测预算。首轮无区间动作校验错误及第二轮15分钟历史裁剪错误均保留，新版本分别修复原SCI接口绑定及完整历史兼容，未改物理参数或服务判据。
