# Annual entry migration and retained historical behavior

Public environment reset/step forms remain unchanged. The SCI constructor gains
one optional `annual_program_data_context` argument. Its default is None; all
legacy selective-input, finite-window and final-blind release guards remain.
The annual entry uses a separately approved, code/input/case/configuration-bound
nonblind grant, without changing the original twelve-day authority or receipt.

The new annual runner retains native physical equations, hardware, permissible
connections, service criteria, priorities, projections and ordinary command
interfaces. It uses the original controller on actual observations and preserves
its exact historical demand minimum; it does not introduce a new controller.
Full causal records and actual histories remain available on disk. Completed
service accumulators use the same arithmetic and material thresholds in order.

Two explicit annual boundary corrections are required:

1. A short pilot retains its existing endpoint source hour. At the actual end of
   the8760-hour input, no terminal boundary solve or hour8761 is performed.
   Unfinished commands/repair/stock recovery remain in the terminal state.
2. M23 removes `model_closure_events` from the native parser scene and stores
   it on the environment for hardware changes. The historical StudyClockMixin
   reads only the parser scene, omitting the registered response wait for these
   detached calendar events. A reproduced event at60.25min returned no delay
   despite a15min setting. AnnualSourceMixin now uses the same detached calendar
   with the existing `response_windows` function: the release is75.25min.
   Future onsets do not extend today's wait. This restores the stated queue
   semantics for the new annual entry; historical outputs remain unchanged.

Historical matched windows retain their own version and assumptions. Numerical
steam closure of those windows does not requalify their command-wait behavior
or make them results from the new annual physical replay.

The new output includes full original solver witness receipts, block identities,
one-time preparation, observed/unknown tails and explicit suspended/failed/
completed states. Typed snapshots require complete field coverage and source,
input, configuration and durable-history identities. They are not terminal-only
state summaries. Controlled resume rejects ambiguous newer/orphan records and
does not delete or reinterpret them as completed evidence.

DiskHistory uses its own versioned lossless gzip typed-row format. Checkpoint
format changes receive their own schema; old files are not overwritten or mixed.
Actual owned process attempts, initialization attempts and continuation
invocations are reported separately. No review archive is generated.

Annual resource admission still requires measured full-vs-resumed physical
agreement and a cross-month pilot. Helper tests alone do not establish bounded
memory/disk/time or real equipment/clinical qualification.

New annual logging/stop migrations (DEV, not applied to epoch04 producers):

- `AnnualSourceMixin._after_actual_segment` first completes the original
  physical hook, then gives the same final accepted result to an output-only
  witness. No additional observation, current-context solve or action-based
  candidate selection is used. `--use-actual-witness` in detached analysis
  requires that new receipt for every segment; absent receipts stay unknown.
  Default historical analysis continues to use the original matching rule.
- Healthy execution permission/boundary lookup maps retain only the active,
  latest-arrived and pending-command support and latest boundary predecessor,
  after the full segment is durably acknowledged. Full historical facts remain
  in original block records. Progress/checkpoint/result metadata records the
  retention receipt; this does not qualify all remaining live state as bounded.
- Native failure `completed_segments`/`events` may be exact typed disk-history
  references instead of inline full-prefix lists. Each includes its complete
  uncommitted tail. Failed-step databases are not committed afterwards; a
  read-only resolver rejects changed/newer/missing prefixes. Native exception
  semantics and ordinary diagnostic fields remain; failures are never zeroed.
  If the native failure occurs exactly at the source-year endpoint, its actual
  error clock/state remain unchanged. Only the diagnostic weather/timestamp row
  comes from the exact last completed actual interval and is labelled as such.
  Missing context/row is explicitly unavailable and retains the primary cause;
  it never reads8761, clamps a physical query or fabricates a successful record.
- `--stop-file` registers one external orchestration path, separate from
  physical configuration and controller inputs. A preexisting flag prevents a
  new invocation; an acknowledged mid-run request forces an explicit suspended
  checkpoint. The runner never removes the request. Resume inherits the frozen
  path and rejects a replacement path; preparation and inventories do not reset.
  The external orchestration receipt stays in its separate file/checkpoint
  binding. It is never an extra field in the exact four-field numeric data grant.
  An actual epoch05 admission failure exposed this mismatch before any numeric
  input parsing; the failed attempt and a real-grant regression are retained.
- Original detailed inequality diagnostics use lower=-Infinity or
  upper=+Infinity, with the corresponding residual=-Infinity, for an absent
  side. The new witness initially rejected these native encodings after the
  first actual0.25min segment. Its correction accepts only those exact pairs
  and labels their meaning after the original JSON sink normalizes them to
  null. NaN, wrong-signed endpoints, invalid activity/violation/raw vectors and
  malformed residuals remain errors. No physical bound/tolerance is relaxed.

Indexed domain evidence migration (DEV, not applied to frozen epoch04-07):

- The original native row writer remains source-pinned and its gzip/ref bytes
  unchanged. A bounded decoded catalogue cache replaces the growing in-memory
  known-reference dictionary; ordered raw-file proofs are stored separately.
- Each new blob is independently decoded/hashed and fsynced. Per-block proof
  and catalogue commits finish before journal acknowledgement, including a
  failed physical prefix. A partial/ambiguous commit remains failed; no rollback
  of committed evidence or automatic repair/truncation is performed.
- Checkpoints store compact exact database descriptors instead of copying the
  entire known-reference map and raw-file manifest. Restart streams the full
  pair/proof/file verification and checks acknowledged sidecar/domain ownership
  before opening the next solver-row writer. Original legacy manifest helpers
  and their tests remain available for their earlier source epoch.
- A failed proof commit retains its public precommit prefix descriptor plus the
  current batch tail. This is labelled unacknowledged and may be unrestorable
  if the database advanced. Driver close receipts are separately fsynced gzip
  files with SHA references, preserving that evidence without embedding it in
  the result. Nothing is silently deleted or replaced by zeros.
- Pending proof memory depends on the acknowledgement batch, not merely the
  decoded-cache size. Remaining journal/result metadata still grows. Whole-year
  memory, disk, time and archival feasibility require measured pilots.
- Actual epoch08 admission exposed the real constructor's absence of a core
  before reset. Index installation now checks for an existing log without
  creating a core; reset remains the only initializer. An early attached store
  is also closed/retained if installation raises before returning. The failed
  zero-minute invocation and exact unreset-constructor regression are retained.

Independent steam-only observer extension:

`--steam-flow-only` requires the owned final actual primal and checks source,
row ownership, service identities and the algebraic HRSG/boiler/heat/absorption/
discard balance. It is initially restricted to exactly zero recovery cooling;
an exact binary electrical starter can be present. Starter power is not steam
production. Full starter eligibility/powered progress, electrical accounting,
recovery context and whole-system validation are explicitly not claimed.

The old default and strict-actual-witness block reports remain identical to their
pre-extension versions. The prior grid-window strict340passed/24unknown result
is preserved. A separately recorded read-only steam-only audit qualifies364
flows, including24 electrical-starter intervals whose starting GT contributes
zero HRSG steam. Raw vectors, producer records and old classifications are not
edited. The observer source files are hashed separately from the old simulated
model root and must remain unchanged throughout analysis. Native unknowns stay
visible in the combined analysis.

The epoch04 short normal and grid-wait cases established exact physical
full/resumed agreement on196 and364 segments respectively. These remain
source-bound pilot evidence, not completed annual results or proof that new
DEV logging migrations have already passed physical replay.

Calendar-registration accounting (unused until campaign admission):

The specified main F/FD calendar requires positive in-horizon external
availability-loss time, distinct from service failure. Derating time, fractional
full-outage-equivalent time, asset sums and joint time have separate fields.
All-up initial availability, native ordered equal-time changes and the left
limit of the year endpoint are explicit. No future recovery is imputed.

Random zero-event years are retained with canonical N/D physical cases and
separate schedule provenance. Nonempty zero-exposure calendars retain F/FD and
every original event: an availability-neutral event can still affect inherited
response clocks, so zero exposure alone does not prove physical equivalence.
An independent review reproduced the earlier incorrect rejection; the old
test assumption was replaced with stronger retained-event/zero-exposure/no-
automatic-reuse checks. Both failing and passing logs remain in the E ledger.
No sampling, failure rate, physical configuration or online input was changed.

Checkpoint-frequency orchestration v2:

The checkpoint interval is now included in the separate hashed orchestration
receipt, its checkpoint binding and the saved loop state. Resume with another
interval fails before a new attempt/writer/environment is opened; it is not
allowed to silently switch to the CLI default. The exact four-field annual
numeric-data grant is unchanged. Frozen earlier source epochs keep v1 receipts
and must continue using their own unchanged implementation; no implicit upgrade
of their checkpoints is supported.

Controlled block/manual stops still force a current checkpoint at an acknowledged
boundary even when periodic checkpointing is beyond the full requested horizon.
The tests exercise both96 and35041 blocks, both stop modes, changed-interval
rejection before new construction, exact continuation and one-time preparation.
Old preexisting-stop assertions are retained with an explicitly matching interval
so they continue to test that guard rather than a different identity mismatch.

This is controlled-stop continuation, not arbitrary-crash recovery. Once mutable
indexes advance, an older periodic checkpoint cannot rewind them. A future annual
invocation may explicitly register35041 blocks (greater than35040 annual steps)
to avoid repeated whole-prefix scans; final/full audits and forced manual stops
remain. Unexpected interruption can still require a full rerun, with its failed
attempt retained. Annual resource admission must allow for that consequence.

Read-only operation quantities and bounded reader:

The separate operation_summary API adds GT request/process/completion/output-edge
counts, native endpoint-convention operating hours, actual DG attempts and state
entries, aggregate boiler functional readiness/steam/restart electricity, and
carrier-specific storage receipts. Given run-initial flags are explicitly not
monthly initial states. Event counts include the observed endpoint; time/energy
integrals remain half-open. Monthly receipt subdivisions without a physical
split remain unknown. OEM cold starts, thermal standby, per-unit boiler starts,
unpriced standby/maintenance and true DC charging remain unsupported/unknown.
The old engineering summary and physical producer are not silently replaced.
Observer code identities are recorded separately from producer code identities.

The selected JSON reader now searches bounded chunks while discarding diagnostics
instead of visiting every character in Python. Captured values keep the same
decoder and size limit. Ignored values still receive only structural scanning,
not a new whole-file semantic qualification. Unit and independent frozen-source
differential tests cover strings, escapes, delimiters and buffer boundaries.
One actual closed block's selected event/segment bytes matched exactly; its
alternating-trial median was15.5324s versus3.3571s. This is a reader microbenchmark,
not a physical or annual speedup claim. Earlier failed attempts remain in E.

Native evidence-source check cache (annual logging only):

Repeated store checks now use at most8 exact binding/method/code/stat entries;
the stat tuple is size, mtime_ns and inode. Changed bindings, another path,
method replacement and same-method code replacement cannot borrow a cache entry.
Creation/restoration/snapshot use a full SHA check, and durable commit is
bracketed by full SHA checks. A same-size edit with a restored mtime can escape
an ordinary cached check; it cannot receive a durable acknowledgement without
the forced complete check. This is local integrity, not hostile-edit or account
authentication. A failure after both databases advance retains its unacknowledged
precommit tail/descriptor; advanced data are never rolled back for convenience.

Native store/ref ordering, raw gzip bytes, row hashes, independent canonical-row
verification, blob fsync and original raw rechecks are unchanged. Tests exercised
changed-source boundaries and ambiguous postcommit closure. A source-check-only
microbenchmark with2000 ordinary checks plus8 forced full checks per trial gave
medians5.14897s and0.410294s with equal returned bindings. Physical/whole-year
speed and equivalence still require a fresh frozen runtime, not this benchmark.

Output-only compiled-input extension (new opt-in annual runs):

The physical leaf adds one import and one final conditional dictionary unpack.
Erasing exactly these two syntax nodes recovers the complete original function
and module AST, including objectives, constraints, solve order and return ports.
The public reset/step interfaces, queues and physical commits do not change.
Capture surrounds env.step only; reset, observation construction and policy
decisions remain outside its context. It copies already-used closure, storage
ports, index map, coefficients, equality rows and dt; it performs no additional
state/model/optimizer query. Unreviewed probe layouts, including tracking layouts
with the same47/48 vector length, remain explicitly unavailable and do not become
physical infeasibility solely because of the recording extension.

The exact final-result hook passes the selected result object after native
physical commits. Its packet is never substituted from an equal-valued candidate.
The new recorder checks raw vector/dt, loaded leaf source code, complete registered
source profile, helper bytes, actual hook frame and object identities, and the
runtime freeze. Packet flags for actual/source/physics qualification remain False;
the separate receipt binds ownership only, not physical feasibility. Missing
compiled inputs retain a basic witness plus an explicit unknown compiled status.

The registry preserves the legacy14-source/legacy-recorder pair. New recorder
plus old14 supports basic witnesses only; old recorder plus new14 is rejected.
Unknown file hashes and mixed releases fail closed. The old steam fixture now
copies byte-pinned original physical source from a new read-only test fixture,
rather than silently mixing a new leaf into a legacy producer. All original
assertions remain. The source cache is bounded to8 stat/code identities; complete
source bytes remain covered by runtime freezes and durable/end binding checks.
Independent negative probes found warm cache hits could skip loaded metadata
checks, and replaced leaf/hook globals or code could borrow disk-only identity.
The new recorder now checks loaded metadata/globals and helper aliases before
cache lookup, includes loaded helper code identities in its bounded key, compares
fresh compiled helper/leaf code on cache admission, and compares actual-hook
code/globals with the static byte-pinned hook. Original failure probes remain
default regressions; this is local process/source integrity, not authentication
of an arbitrarily hostile interpreter or hardware.
Direct helper callables are checked by their actual code, without generic
unwrapping. Only capture_scope's exact stdlib contextmanager wrapper and its
single original generator closure are accepted; a decorated replacement cannot
borrow the wrapped function's provenance. Independent cold/hot negative probes
were retained and re-run after this additional finding.

New source requires its own full default suite and matched actual normal/fault
pilot before any annual use. Independent observers must still reconstruct every
E/steam/C coefficient from registered formulas and compare original owned rows;
matching Aeq*x alone cannot authenticate the compiled matrix. No OEM startup,
control DC energy, hot-standby, clinical or whole-year qualification follows.

Incremental interruption recovery (new runs, explicit opt-in):
`--recovery-every-blocks 4 --recovery-vault E:/.../case-vault` registers a v4
external-orchestration identity. The existing checkpoint interval, recording
mode and exact registered external stop path remain bound. Omitting the two new
options preserves legacy v2/v3 behavior and strict advanced-prefix rejection.
The runner performs no extra reset, observation, policy decision or physical
solve. Snapshots are taken only after the native durable block acknowledgement,
history commits, execution-map compaction and prefix-part close.

Each immutable recovery point contains the existing exhaustive typed runtime,
controller/mailbox aliases, RNG, queues, stock/readiness state, observer and
accounting accumulators, mutable history tails, exact SQLite headers, and new
rows of the two registered history/catalogue schemas. Only newly acknowledged
raw blocks, solver sidecars, actual-prefix parts and native domain blobs are
hardlinked into the vault with original SHA/size bindings. Mutable registration
and invocation metadata are copied, never hardlinked. SQL deltas and typed JSON
use fixed gzip level1; original physical rows/raw gzip bytes are unchanged.
COMMIT is published last and LATEST advances atomically afterwards. A prepared
or damaged point is not called restorable. After the first complete point, an
unexpected process loss can discard at most the configured number of 15-minute
blocks, counting an unfinished block: the writer does not start another block
while COMMIT is being saved. The point being saved is
not guaranteed until COMMIT; disk/power destruction and arbitrary hostile-host
authentication are not claimed.

`python -m tools.annual_program.recovery restore --vault VAULT --snapshot latest
--output NEW_DIRECTORY` authenticates the complete selected chain once and
returns JSON containing `resume_checkpoint`. Feed that marker to the unchanged
`--resume-checkpoint` entry with the same frozen source/input/case/config/mode,
stop path and recovery settings. The output must be new. No original producer,
newer journal, partial sidecar or live database is truncated or overwritten.
Recovery uses exact logical SQL row bytes/headers and original mutable tails;
SQLite container/page bytes are not claimed identical. The original attempt may
be absent: the vault contains all required raw/index/runtime preimages.

The restored producer is a distinct branch. Its migration ledger preserves each
original raw/index record, new branch record and the precise path patch. The
raw-block whitelist is only `solver_row_sidecar.path`; no physical value or
source witness field is rewritten. Registered descriptor paths/checksums and
journal/publication paths are rebound to the new directory. Historical SQLite
payloads and hash chains remain byte-identical, including original provenance
strings. At final RESULT materialization, only sidecar receipt paths whose
origin appears in the sealed recovery origin chain are mapped to the new
producer; original gzip SHA/size and every other receipt field stay exact, so
independent readers retain their strict membership checks. A previous branch's
origin receipt is retained separately before publishing the current origin.

Normal periodic publication reads only new SQL/raw ranges and the complete
bounded runtime document, not the old raw prefix. Snapshot statistics report
new SQL rows/raw members/bytes, compressed SQL/runtime bytes and actual elapsed
time. A new generation after branch restoration archives one complete base;
that one-time prefix cost and full restore/final audit are explicit. Frequency
and 35-day parallel resource admission require measured gate overhead. The
historical 782-hour interrupted output remains incomplete and read-only; this
feature does not retroactively create a recovery point for it.
## Opt-in accepted numerical-result cache (2026-10-31)

`run_case(..., accepted_result_cache=True)` and CLI
`--accepted-result-cache` enable the reviewed process-local cache. The default
remains disabled. The external orchestration freeze advances to v5 only when
enabled and binds exact-problem mode and its estimated memory budget. The first
v5 release used 512 entries. The faster v6 release admits 2048 entries under the
same 32 MiB bound and keeps the explicit 512-entry helper option compatible.
The cache starts after physical reset/warmup and starts cold after restoration;
its entries are not plant state and are not inserted into physical checkpoints.

The complete original and scaled numerical problem, objective, bounds,
integrality, row metadata, options, numerical policy and source identity form
the key. Only first-attempt accepted native results enter the cache. A hit is a
fresh attempt record with current original-domain, objective, gap and time-budget
validation. Its provenance explicitly states that native optimization was not
performed on that call and links the accepted origin certificate. Failed,
uncertain and recovered native attempts remain explicit and are not cached as
successful first attempts. Results are copied and the cache is bounded.

This is exact numerical reuse, not approximate load/inventory rounding. Native
solver parameters, acceptance tolerances, physical capacities, service locks,
startup clocks and failure standards are unchanged. Aggregate cache/native-call
counters are execution metadata; logical calls must not be counted as new native
optimizations. The separate reviewed source release retains all older observer
source contracts and authenticates the new helper outside the original sixteen
compiled-packet source fields. Unknown and mixed releases still fail closed.
