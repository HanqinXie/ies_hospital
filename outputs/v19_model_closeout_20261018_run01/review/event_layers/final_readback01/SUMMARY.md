# 最终四类与事件层实际计数

事件 collector 在 R2 的 136 批、394 条非正常轨迹全部接受后实际执行 **1 次，exit 0**。本表覆盖其中 main 80 规格×3策略、confirmation 32 规格×3策略、传播 ON/OFF 6 规格×3策略，共 354 条；不把 normal、long、时钟敏感性或 compatibility 结果混入此分母。confirmation 是 8 背景×4机制，不是 32 个独立背景。

下表为实际记录的残余应力保护事件数，策略顺序为 E/K1/C19。禁止反送隔离、最小出力联锁在全部 354 条中均为 0，仍作为独立类别保存，未并称为残余应力跳闸。

| canonical 类别 | main 每策略规格数 | main 残余应力保护 E/K1/C19 | confirmation 每策略规格数 | confirmation 残余应力保护 E/K1/C19 |
|---|---:|---:|---:|---:|
| L1 单设备故障、传播关闭 | 20 | 0 / 0 / 0 | 8 | 0 / 0 / 0 |
| L2 同配对故障、允许传播 | 20 | 1 / 2 / 0 | 8 | 1 / 0 / 0 |

L2 的 main E 1 次发生在 `main_final_r1_001`：GT1 于 82.5 分钟；K1 的 2 次也都在该同一案例，分别为 GT1 于 82.5、GT2 于 100 分钟。confirmation E 的 1 次在 `confirmation_final_r1_025`，GT1 于 105 分钟。因此 main L2 的受影响案例数为 E/K1/C19 = 1/1/0，不是 1/2/0 个案例。L2 是允许传播的设计类别，不能把每个 L2 规格当作已发生级联。

每策略的外生设备故障开始/返回标记数分别为 main 60/60、confirmation 24/24、传播面板 6/6。L3 无初始设备故障，设备故障标记为 0，需求冲击不因此被改写成设备故障。外生标记与继发保护独立；本表也不把“无保护事件”解释成“无 ENS”。

ON/OFF 有 **93 个 registered_full 逐策略配对**全部通过实际元数据匹配：main 60、confirmation 24、传播面板 9；两窗口共 186 行。登记定义匹配与实际匹配分列，后者核对输入清单与实际 reset，并先将两侧已应用事件定义的摘要分别绑定各自 manifest，再仅移除两个传播开关字段进行跨 ON/OFF 比较。不同的完整事件定义摘要没有被机械要求相等，也没有声称策略相关的故障前 injection 状态完全相同。

专门传播面板的三个 ON 案例中，E/K1/C19 各记录 3 次保护事件，均为 GT1 在 37.5 分钟；三个匹配 OFF 案例各为 0。C19 在 main L2 的零次结果不表示取消传播：main L4 仍有 2 次，专门传播 ON 面板仍有 3 次。

严格 [0,600) 与完整注册窗分别保存；本表完整注册窗为 600–900 分钟，本次两窗口的目标事件计数恰好一致，没有将更长尾段裁成 600 分钟。24 个实际继发事件全部标记为 `continuous_residual_stress_surrogate`；这是已实现研究代理的实际记录，不是 OEM 或临床事故校准。

目标事件计数的未知 case-window 数为 0，所有选中轨迹完成且原 audit 通过。健康设备功能失源没有独立日志，故其事件数仍为 **null/not_directly_logged**；健康 HRSG 失去排气源、健康 ABS 失去共用塔排热的开发代表仅作为单独派生条件，未外推成最终全体计数，也没有把设备零出力等同故障。
