## 是否需要 root 立即处理资源

当前没有失败证据，也没有资源门槛被绕过的证据；comparison 正在两路推进，暂不需要关闭进程、改变系统或修改模型。用户已表示会自行关闭大程序，之后应按新的真实 available/commit 读数判断，不能预先承诺释放量。

有一个明确的后续风险：本次 commit headroom 11.97 GiB；即使仅按两个 child 当前 private 自然释放估算，也约 17.70 GiB，仍低于 K1 72h 的 19.123、C19 48h 的 27.519、C19 72h 的 35.613 GiB。其他进程/child 后续增长或释放会改变该算术。当前物理可用也低于 C19 48/72h 门槛。故 **最终大窗口可能进入等待，等待时间不能计为科学失败或零耗时**。

正常阶段由已审查的串行 helper 继续做 case-specific 双资源准入即可。若用户关闭程序后，大窗口仍等待且实际读数长期不足，root 才需要据当时读数向用户报告资源缺口；本报告没有依据建议降低门槛、主动关闭用户程序或更改 pagefile。
