二、研究目标与共同规则

目标是使模型在正常、故障、恢复及再次扰动过程中，正确处理：
“实际电源与库存—设备与支路状态—电热冷转换—必要辅机—实际服务—恢复过程”。

继续保留 P0–P3 与电、热、冷主体结构，可靠性优先于费用，费用优先于排放。不使用 MPC，不引入 ML 预测器。无需完整电网潮流、厂家级黑启动、电池寿命或全院精细管网。

所有方案共用物理模型、初态、设备容量、观测规则、命令队列、通信与执行时延、保护及本地执行权限。策略名称、场景标签不得决定物理行为。

控制器只能使用当前及过去可获得的信息。未来故障、修复时刻、停电终点、未来真实负荷和场景表只属于场景发生器或事后评价，不得进入在线决策。

不要要求 A 获胜，也不要要求新模型的所有指标都优于旧模型。补上真实站用电后，保障时间缩短可能是纠正旧模型的乐观估计。旧新物理模型比较与同一模型下的策略比较分开。

本轮核心验收是解决下列具体问题，而非穷尽所有参数或证明所有工况全局最优。

三、最高优先级：修复恢复过程中的无效等待

V22 的 067 案例中：
- 外部故障在 780 min 解除；
- 780.5 min 电网实际接续、站电恢复；
- R 已有到达的正锅炉许可，支付共同 1 min 复归后于 781.5 min 恢复关键供热；
- C/A 当时仍为零锅炉许可，直到 795 min 新许可到达，796 min 恢复；
- C/A 多出的 14.5 min 是报告明确指出的命令/决策代价，不能解释成不可避免的硬件启动时间。

先用实际过程数据复现上述链条，核对报告是否准确，再修改。重点检查是否混淆了：
1. 当前设备能够实际交付的功率；
2. 可以预先保持、等待真实供电条件成立的合法准备许可。

优先在原有决策周期和命令队列内解决，例如根据已经存在的关键热需求保留有条件的准备许可。许可已到达不等于设备已启动；只有实际站电、设备资格与其他必要条件满足后，才能支付启动电、推进复归计时和实际供热。

若需要新增“可观测状态变化触发重新决策”，应定义成全部策略共同可用的接口，写清观测与命令时延。不能仅给 C/A 即时行动权限，也不能把看到修复后的重算效果倒算到修复之前。

特别禁止：
- 读取未来修复时间提前安排；
- 把硬件修复直接等同电网已接续；
- 绕过尚未到达的命令或真实复归时间；
- 把备用正许可当成当前实际辅机耗电，用它虚构 GT 的电力消纳。

验收：
- 保留 V22 基线及修正后的同条件完整过程。
- 分别记录硬件恢复、合法观测、指令发出/到达、实际站电恢复、启动电支付、复归完成和实际供热时间。
- 增加“硬件恢复但电网未实连”“站支路仍断”“正许可尚未到达”三个负例。
- 检查未恢复、再次掉电、恢复途中失去站电时，计时器和能量正确处理。
- 有合法改进就实际实现；仍有等待则明确是哪项约束造成，不强行规定所有方案同时恢复。
- 将同样逻辑检查到冷源、泵与其他受许可约束的恢复路径，修共性问题，不为067写专用分支。

四、最高优先级：解决冷库存耗尽后的数值微脉冲与可靠性统计失真

V22 cold_partial 的原始统计为18次中断、最长约1min，但17个间隙合计只有约111.16微秒，间隙交付关键冷量约2.31e-6kWh；工程过程接近持续17.064466min的缺冷。总ENS接近正确不代表次数与最长中断也正确。

请沿真实调用链定位，而非先认定某一个原因：
- 耗尽事件的定位与步长；
- 接近零的库存是否重新开放放冷端口；
- 是否有极小实际回充后重新放冷；
- 求解器容差与单位尺度；
- 时间端点、重复事件与服务判据；
- 充/放/空闲模式切换；
- 统计程序是否将瞬时数值满足误认成实际恢复。

先输出首次耗尽前后的小段原始证据：分段起止、初末库存、充放功率、充放能量、泵电、各级交付/缺口及触发原因。试探求解不得提交库存或推进时钟。

源头修正须满足：
1. 没有真实补给时，耗尽后不能靠数值残量反复恢复。
2. 若需要数值归零、端点规范或模式滞回，给出有量纲的误差界及能量处理；不得凭空补能或随意截掉真实库存。
3. 不放宽物理守恒和设备约束来消除报错。
4. 固定上层决策/命令到达时钟，仅改变必要的积分或事件定位精度作少量收敛检查，避免把更频繁调度的收益误称数值修正。

同时修正“什么算一次恢复”的工程定义：
- 原始功率、库存、ENS及原始事件记录保留。
- 新版本允许采用清楚、预先登记的恢复确认条件；电、热、冷可按其意义分别定义。
- 现有1s工程等效带不能未经论证直接变成所有服务的恢复时间标准，更不是临床标准。
- 真实的短时电力中断仍须可见，尤其不能吞掉原10s启动或15s开放切换造成的事件。
- 旧V22统计保留，新统计标明版本和定义，不能覆盖旧结果制造改善。

验收至少包含：持续缺冷中夹微小数值间隙、真实恢复后再次失供、真实短时电中断、库存为空且无回充、合法回充后再放冷。新结果应让次数、最长中断与实际过程一致，而不只是报告“已知局限”。

请检查实际代码及触发条件，补齐有必要的少量离散运行域，例如停止、已许可启动、合法正出力，并与已有GT子集和储能模式检查协调。可采用有界枚举或其他清楚方法，不要求通用大规模非线性求解器。

区分上层命令生成与实际执行：

- 实际执行只能用已经到达的许可；
- 当前只有零许可时，不得通过搜索正出力域扩大执行权限。

各候选必须来自同一快照、使用同一服务优先级和约束；失败试探不改变库存、启动次数或计时器。正运行域必须对应真实设备运行、实际辅助电和合法热/汽去向，不得靠伪负荷、免费弃电、额外外送或容量之外的储能充电口补可行性。

验收：

4. 无合法电力消纳时GT仍应退出。
5. 区分局部候选拒绝、编译实现缺口、已检查域内不可行和后验乐观上界，不混称全局物理无解。

六、核清站AC/DC边界与四类情景的实际含义

A. 用最小连接表说明站电范围

现有站AC中断案例增加热缺口，而关键冷ENS与冬季H1基准相同。这不自动是错误，需要先确认STATION_AC究竟代表什么。

建立一张“电源→母线/支路→设备负载”的紧凑表，列明：
建筑UPS、锅炉辅机、GT启动、EC主电、ABS/塔辅机、建筑风机/输配泵、DG专用启动DC。

若STATION_AC只是锅炉/GT启动支路，准确命名并说明制冷设备由哪里供电；若表示全站母线，核查应受影响的设备是否遗漏。按拓扑修正，不要任意把所有设备接到一个母线，也不扩成完整配电网络。

DG的1440min/2次专用DC资格可保留为明确研究简化，但要检查取消未开始请求、实际失败启动、资格恢复与第三次请求的状态处理。没有回充模型时不能偷偷恢复耗尽资格；也无需本轮新增电池寿命经济模型。

锅炉1min复归、GT10kWe启动等量级假设可以继续使用，但补做已登记短/长复归与低/高启动功率的少量针对性过程，检查结论是否依赖单一参数。0min若使用，只作为理想下界，不包装为真实冷态启动。

B. L2不能只剩一个名称

默认隔离未经校准的GT研究应力代理是合理处理，但必须核查：在同一背景和外生故障下，关闭代理后，L1/L2是否仍有实际状态或保护过程差异。

先比较真实recipe、物理配置和事件记录，不能凭标签下结论。基本能源依赖和物理保护对所有策略、所有类别一致；不要为了区分L1/L2，在L1中取消必要泵/风机依赖。

优先利用现有设备关系完善一条有工程依据的过程：
“必要供电/流动条件丧失→设备不可运行或保护性退出→上游恢复→满足复归条件→设备恢复→下游服务恢复”。

明确区分功能不可用、保护性锁定、普通调度停机与永久设备损坏。没有依据就不声称硬件损坏。保护条件须来自实际状态或明确的物理代理，不能把未供需求加到GT实际功率上冒充真实过流。

至少验证触发、不触发、恢复/复归三个过程；有合法运行调整能避免传播时再验证该动作，不强制每例产生继发故障。

若某些L1/L2配置实际等价，应明确记录等价并调整分类解释。开/关某传播假设可作显式机制对照，不能把不同物理模型伪装成同条件策略比较。不为了保留“四类”名称制造故障。

七、温度：明确授权补数据和有限结构改进

V22已改进净显热输入、状态连续性与恢复能量接口，但完整加热输入仍是60min，目标要求不超过10min；0/16是四种方法乘四个已见日期，不是16次新的独立验证。一次拟合和3次端口求解没有完成温度精度及完整IES恢复过程验证。

本轮不继承“一次拟合之后必须停止”的僵化限制。允许完成以下受控工作：

1. 使用本机现有EnergyPlus版本、原医院IDF与EPW，在派生副本上真实补算少量高分辨率案例，不升级或改写原工程来凑结果。
2. 先做一个短pilot，确认温度、完整供热/供冷、事件和恢复输入全部齐全、同一时轴、单位与倍乘正确，再运行小批配对案例。
3. 优先采用5min共同输出网格，必要时保留更细HVAC原生区间。不得把小时数据插值或复制后称为真实5/10min输入。
4. 建议规模为冬夏各一个校准日、各一个未参与选择的检验日，每日正常参考/短停冷/长停冷，约12次运行；这是覆盖建议而非必须跑满的数量。
5. 保留预运行、墙体热状态与足够恢复尾段；共享盘管按真实服务范围干预，不把共享盘管关闭称为单房间独立故障。

热量口径：
- 明确使用绝对送达显热，还是相对正常参考的显热变化，背景负荷必须与之配套。
- 从本机输出变量字典核对区域实际送达显热、内部得热、通风/渗透、区际交换、表面对流和蓄热，避免漏项与重复计量。
- 区域实际送达热量不能再与同一路径盘管热量重复相加；机械新风已经体现在送风显热中的部分不能再计一次。
- 表面对流、墙温等EnergyPlus真值可用于诊断和校准；低阶模型运行时不能依靠事故后的真实墙温、未来室温或真实表面热流来冒充预测。
- 修正区域/等级映射与倍乘，不能把整个P0的冷量直接当成一个代表房间的交付。

模型顺序：
先用正确输入重新检查现有低阶模型；若误差具有明确的慢热状态特征，允许增加一个墙体/室内热质量状态。固定校准集，进行有界且物理可解释的参数求解，允许必要收敛和初值检查。结构与参数冻结后再看检验日，不按检验结果逐日调参或重置隐状态。

沿用已登记工程精度目标，除非在看新检验数据前证明原定义不适用并透明修订：
- 事件段RMSE≤1℃；
- 恢复阶段开始后的前6h RMSE≤0.5℃，明确并沿用已登记的恢复阶段起点；
- 最大误差≤2℃；
- 首次研究越限时间误差≤10min；
- 恢复时间误差≤20min；
- 完整输入间隔≤10min。
这些不是临床标准。没有越限、漏判越限、未恢复与观察窗不足须分别处理，不能删掉不利指标取得通过。

至少再做少量完整IES运行，把实际供冷受限、温度状态、恢复附加冷需求以及真实冷源/风机/泵电接起来。不能只凭3次独立端口求解宣布完成动态闭环，也不能把恢复冷量重复计入原需求。

停止条件：完成正确输入、一种有依据的结构修正和冻结后的新日期检验后，若仍未通过，就明确降级为探索性温度输出，保留已验证的恢复能量接口，不用于关键保障或安全判定。不要无限增加状态或搜索参数。现场接线图和OEM资料不是补算DOE原型温度输入的前置条件。

九、补齐可检查的恢复数据与轻量源码交付

本次审查只能看到报告、README和RUNS.csv，V22尚未推送，新源码与PROCESS未随附。下一轮必须让关键结论可以直接检查，而不是再增加无法复核的描述。

RUNS.csv中的critical_union_recovery_minutes及observed对应列在71条记录中全部为空。先查清字段映射和定义：

区分绝对恢复时刻、从故障解除起的等待时长、从实际可用电源恢复起的等待时长。评价器可以事后读事件事实，控制器不能据此提前决策。

十、自主推进与完成标准

可以并行处理恢复/求解、微脉冲/指标、温度三个独立工作包；在同一最终物理核心整合。常规修改、重构、参数边界检查、少量EnergyPlus新运行和受影响回归均已授权，不逐阶段询问。

按“复现具体问题—修改—正例与负例—受影响完整运行—一次集中回归”推进。测试检查真实物理关系和事件过程，不复制实现公式或检查文件存在来凑数量。文档/格式变化不触发不必要的物理重跑。

保留旧结果和真实失败；新版本可以修正实现与指标，但必须保持来源及定义清楚。不要把精度门槛调到刚好通过，不因一次试探失败宣布全系统不可行，也不要把无法解决的部分藏进成功汇总。

最终用工程语言逐项回答：
1. 电源和设备恢复后，哪些额外等待被消除，哪些仍有真实约束？
2. 冷库存耗尽后的微脉冲根因是什么，次数和最长中断是否已可信？
3. 合法运行域是否还存在已知漏查，失败时怎样处理？
4. L2实际模拟哪一种传播，站电支路作用范围是否明确？
5. 温度是否完成高分辨率验证，未通过时保留什么使用边界？
6. 同条件下关键服务、一般服务、费用及库存付出了什么代价？
7. 哪些部分已验证，哪些只是合理假设，哪些仍然缺证？

不要仅以“测试全部通过”宣告模型正确。也不要把厂家参数未齐全当成所有工作的阻塞项。本轮应交付一个可以检查关键供能、恢复和可靠性指标的模型，不要求证明所有故障无中断，不要求产生唯一最优策略。
