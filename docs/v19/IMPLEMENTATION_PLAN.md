# V19 model closeout implementation plan

> Agentic execution uses test-first changes and independent review. The V19 task explicitly authorizes autonomous design, implementation and evaluation; internal checkpoints do not require another chat approval.

**Goal:** Separate service requests from involuntary unserved load, close transfer/recovery semantics, compare one transparent finite-energy reserve alternative, and freeze an explainable paper model.

**Architecture:** Create `tools/model_closeout` without editing `tools/execution_recovery` or prior outputs. Fork only the three affected planners and the versioned environment/runner adapters; inherit unchanged physical balances, numerical certificates, source data and original service/protection criteria. One owner changes the shared execution core. Independent workers own emissions, model specification and confirmation-pool metadata.

**Tech stack:** Existing Python/Gurobi/NumPy simulation, pytest, CSV/JSON/Markdown evidence, existing lossless delivery tools. No MPC, learning or new physical equipment.

## Design choices and bounds

1. **Selected:** Independent ordinary contact variables for all four priority groups and all three carriers; retain unmet exclusively as present balance shortage. Explicit contact-selection objectives and conditional source permissions must jointly support a future-arrived request under the existing observed readiness assumptions. E/K1 migrate the common meaning with original reserve/cost preferences intact. The executor still honors explicit isolation/cuts. **Rejected:** blanket executor reconnection would erase intentional safety actions; output-only zeroing would lack a joint original-domain certificate.
2. **Selected:** A bounded grid-return wait governed by current real DG support and currently RUNNING GT bridge feasibility, with a declared timeout and immediate fallback if current support disappears. Pending GT and destination GRID do not supply OPEN. Preserve the original finite PREPARE/OPEN and no parallel operation. If no legal bridge is obtained, log and accept the chosen finite interruption.
3. **Selected:** First remeasure positive contact delay after the semantic fix. Improve ordering only within existing real load and original unloading capability; otherwise publish the 0/0.25-minute applicability boundary. Do not defer no-export protection or count pending contacts as an energy sink.
4. **Selected:** Two finite-energy variants only: the inherited service-rich C18 preference and a declared current-critical-energy-reserve C19 preference. Parameters use current critical demand, necessary conversion auxiliaries, remaining shaft budget and observed hardware, never the eventual outage duration. Short/medium/long paired checks disclose lost lower-priority service. Stop search after this comparison.
5. **Selected:** Ex-post emissions evaluation, not a new CO2 optimization objective. Source-specific grid and HHV gas factors; representative OEM-based diesel shaft-equivalent conversion is explicitly conditional, with low-load/start uncertainty. Report known grid+gas subtotal separately from conditional total.

## Stop and interpretation rules

The endpoint is a coherent frozen research model and completed fair comparison, not a universal winner. Shared-tower hardware loss, initial starts, finite-energy loss, finite switching gaps and absent field/clinical certification do not trigger unbounded optimization. Only a new substantive semantic, conservation/interface contradiction or evidence gap reopens its dependent branch. Old results remain read-only; a later success never fills an earlier unknown tail. Full historical pytest and field validation are distinct from the exact targeted tests actually executed.
