# 模型和算法说明

本说明依据本次上传的源码进行整理，不改变模型。原始字节与来源见 release/SOURCE_MANIFEST.json。

## 系统与输入

能源站包含燃机—余热锅炉、锅炉、吸收制冷、电制冷、电网、柴油、共用冷却塔和循环泵。终端按P0–P3服务分层，显式处理建筑直接电、风机及冷热输送辅助电等依赖。输入沿用DOE/EnergyPlus的IDF、气象与8760小时数据，设备参数来自历史源表与明确的研究缩放。该组合不是对某真实医院的完整数字孪生。

## 调度算法

上层使用词典序分层混合整数优化：逐层最小化目标，加入 `J_i(x) <= J_i* + epsilon_i` 的显式锁后再求下一层。目标包括已到达权限下的当前P0/P1服务、主动支路断开、其他服务、所选策略的准备目标、有限后备支持、费用及末级择优。具体顺序由策略和当前状态决定，不是所有时刻固定五层，也不能概括为所有P0–P3目标永远先于全部准备目标。

主实现：`model/tools/sci_engineering/planner.py`。求解后端：`model/src/hospital_ies/solver_backend.py`。

线性设备约束与离散启停形成MILP。SF2路径将燃机运行燃料 `Fdot = a(T) P^0.673` 作为非线性关系接入，相关求解属于混合整数非线性问题。使用Gurobi原生接口；SF2精确非线性路径要求Gurobi13。源码中保留的旧函数名或MILP错误文字不能代替实际数学问题分类。不是神经网络调度、遗传算法或粒子群调度。

## 年度方法

- M_available：当前服务和经济调度，保留当前观测下的锅炉可调范围机制；它仍使用优化器，不是无人干预组。
- M_ready：M加因果的在线机组准备及转换重查。优先选择当前运行且可用的机组，否则按固定机号选可用机组，发出最低稳定出力准备请求，仍经原队列和执行约束。
- C_ready：协调当前服务、条件性失源准备、启动桥接、响应时间和有限后备资源，并接入ready机制。条件计算不读取真实未来事故日历，不提前推进库存和启动时钟。

配置为准：`annual/normal_year/cases/`。当前主流程没有MPC或在线未来事故脚本。局部研究中的R1/R2恢复规则不自动等于年度已安装模块。

## 命令与执行分离

每15分钟根据合法当前/历史观测生成命令；队列、到达时刻、启动、爬坡、最短开停机、转换和连接决定其执行。实际供能计算受已到达权限和当前物理条件约束，不能授予未到达命令权限。实际供能环节也存在约束求解，但不应据此称为数学意义的双层优化。

流程为：结算上一段 → 当前事件及旧命令到达 → 合法观测 → 新命令生成 → 排队 → 事件子段实际运行 → 服务、温度、燃料和库存结算。物理子段最长1分钟，事件处继续细分；原小时输入在原小时边界更新。当前计算不是原生分钟负荷仿真。

## 传播、动态与恢复

故障经电—汽—冷和辅机依赖传播：燃机退出同时减少电与余热；停电影响辅机与启动；塔受限同时限制多条冷源；泵/风机受限可使有源能量无法交付；持续缺供影响库存与温度。功能受限、服务失效和继发设备跳机分别记录。当前年度注册表的 `research_stress_proxy=false`，不得把旧GT残余应力跳机代理视为已启用年度机制。

冷机上升/恢复采用一阶解析响应和区间平均供冷，物理故障削减即时裁限。燃机保持与线性爬坡的运行燃料按解析式积分。连续库存采用 `dE/dh=-lambda E+eta_c Pc-Pd/eta_d`；定位耗尽或充满边界后分段。温度、库存、燃料、设备状态与队列跨故障、修复、月界和断点连续保留。设备修复不等于服务恢复、库存补足或再次就绪。

## 无人干预对照U

`studies/fixed_prefault/source/` 保留最新普通源/专用源分组的冻结比例算术执行。共同故障前准备可以优化；分叉后U禁止新增优化、候选择优和优先调度。普通源按故障前固定份额分配，需求封顶后剩余不转供；专用源保留原连接与有限库存。旧命令到达、机械保护和启动仍执行。它不保证与响应组曲线分离或响应组必然占优。

## 数值加速与证据

年度 engineering_fast_v1 仅复用满足线性、非负目标系数、自然下界严格零及候选目标严格零条件的中间层，并重新检查当前全部约束、界、锁与整数条件。非线性和一般正成本最优解不复用。实际原生求解保留原参数，未启用生产暖启动/模型池。缓存命中记 `optimizer_called=False`，不能伪造原生OPTIMAL。

历史RF、GRU、行为克隆代码保留为研究历史；当前年度不调用其权重生成调度。源码完整性、软件测试、模型内效果与现场/OEM/临床资格分别解释，不能相互代替。
