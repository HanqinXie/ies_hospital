# 保障能力的必要条件与扫描口径

这是预登记的数学诊断方法，不是已完成的边界结果。在线策略只见当前/历史状态；下述离线界可使用完整需求和事故持续时间，必须单独标注，不能作为第六个同信息控制策略排名。

## 供能路径条件

基础设备中 EC 和 ABS 共用散热路径。共享 TOWER 的实际可用散热能力为零、且无登记独立冷库存/冷源时，两种制冷机都不能向区域持续供冷。GT 或 DG 还有电、厂站有名义制冷容量，也不能消除这个路径断点。

区域风机、冷冻水泵或供热循环泵缺少所需电力/可用能力时，相应热冷服务受实际辅助约束限制。H1 不能修复损坏的泵，H2 蓄冷仍依赖登记的输配泵和风机；这些反例应在硬件比较中保留。

风机约束针对空气侧热冷服务。原 P3 热残差内有可追溯的生活热水项，修正模型允许至多 `min(原P3热请求, 同小时来源DHW热量, 当前连接P3热请求)` 不受风机约束；它仍受共用热源和登记供热泵约束。这是可识别非空气侧热量的最大许可上界，不能据此声称单独计量了实际生活热水交付，也不改变 P0/P1 分类或统计分母。

## 需求增幅 × 散热能力

令 `q_c(t)` 为按原区域分类计算的 P0+P1 冷请求，`Q_rej(t)` 为共享散热实际能力，`s_c(t)` 为独立冷库存实际放冷。

EC 每单位冷量的最低散热需求为 `r_EC=1+0.77/3.51685≈1.21895 kW_rej/kW_c`。ABS 还需排走驱动热量，在原模型中其散热比更大。因此，对 H0，

`q_c(t) ≤ min(EC+ABS名义可用冷能力, Q_rej(t)/r_EC)`

是一个故意乐观的必要条件：假定电力、驱动热、转换和执行立即足够，不计准备和部分负荷限制。违反即可证明瞬时关键冷请求无法全供；满足不证明能供，仍可能受电力、热源、辅助设备和实际执行限制。

H2 有冷库存时将左侧改为 `max(q_c−s_c,0)`，并同时限制放冷功率、可用库存、损失和泵电。不得拿没有冷旁路的 H0 公式错误否定 H2。对于有限库存，按时间积分的净缺口不能超过实际可放能量及窗口内真实充值，不能把初始库存反复使用。

扫描的显式坐标为 `demand_amplitude` 和 `rejection_capacity_kW`，不是未经说明的任意故障比例。每个比例与原 TOWER 4220.223… kW 相乘后写成实际 kW，保持主试验设备不变；这是独立能力配置/降额轴。所有策略在同一点用相同能力。

## 故障持续时间 × 初始轴功备用

第一层报告主基础系统的真实首次关键中断，包含 15 min 接续。第二层报告实际首次恢复全部 P0/P1 能源服务后的再中断、有限能源耗尽与观察时长，以免初始等待掩盖后期能源边界。未恢复为未观察到稳定保障；恢复后到窗口末仍无再缺口为右删失。

普通 GRID 故障中，GT 的管道燃气未设置额外库存上限，因而可能在窗口内不受 DG 预算约束。应如实报告“未观测到备用能源界”，不能为了得到漂亮边界图虚构 GT 油箱或称无限持续。

额外登记多源失效诊断（GRID 和全部 GT 同时不可用），用来隔离有限 DG 能源作用。它不是 L1 单设备事故，不能混入主四类发生率或策略排名。若没有其他实际电源，则必要条件包括：

1. 任一时刻关键建筑电与被电供冷等附加功率，不得超过实际已接入 DG 与登记 UPS 的功率上限。
2. 先明确同一积分窗 `I=[t_a,t_b]`。在最乐观、忽略窗内损耗和额外启动代价的电侧上界中，累计必要电输出不得超过 `B_DG_remaining(t_a)+E_rotor_allow(t_a)+E_UPS_allow(t_a)+E_other,e_allow(t_a)+W_external,e(I)`。其中B是积分左端实际剩余轴功等价预算；E_rotor是该时刻已有转子动能的可用上界（kW·s须除3600转kWh），不是机械功率Pm；UPS及其他库存也必须取该时刻已经存在、按已登记效率可交付的电侧能量。为保持必要条件宽松，可将全部初始转子动能视为可用而暂不扣最低转速/接点限制；这不证明该能量实际可执行交付。W_external仅记窗内尚未计入上述预算/库存的真实外来输入或充值，不得把同一DG轴功、转子充能或储能充值重复相加。冷/热库存不能直接以kWh冷/热加到电能界，应减少相应必要转换电需求或明确给出电等价上界。违反这一同窗宽松上界才足以证明能源不足。
3. 更紧界可以利用原转子/轴损、功率和实际冷/热转换关系，但必须列出是模型内诊断，不能改称真实燃油保证。

积分起点与预热另列：当前reset构造的DG转子静止，`E_rotor(0)=0`，初始轴功库存由场景`initial_reserve_kWh`在reset赋值。本次已登记持续时间×备用面板的事件从60 min开始，0–60 min外电正常且未允许并网DG，按当前契约DG保持OFF，因此其60 min事件窗左端转子项仍为0；这是登记条件/源码推论，不是尚未执行的边界结果。若把积分左端移到DG启动后的实际接续时刻，必须改用当时剩余轴功及已有转子/库存状态，不能继续使用reset的完整轴功预算再加已由该预算充入的转子能。事件前的真实储能充值只通过左端剩余库存带入，不能把预热购电全部当成可携入停电窗的能源；若从episode 0积分，必须连同0–60 min已交付能量、损耗、输入与库存变化一并同钟记账。任何其他已有库存或后续真实补入能源也须按同一原则登记。

不依赖特定控制历史的硬件路径或同初态能源必要条件首次失败，可以给出对应假设下的乐观物理上界。若积分左端改为某方案已执行后的状态，该界只从该实际剩余状态起成立，不能声称其他早期运行也会留下同样库存。所有受测在线方案都失败、但尚未违反适用的物理必要条件时，只能说该运行/执行组合未保障，不能证明任何控制都无法保障。

## 实际执行段电端口条件界与快照时序

`execution_limits.effective_dispatch`是boundary调用时的观察快照。共同模型随后可以按已有本地规则修正GT最低出力或执行有限下降，不能把修正前快照直接当整段电源上界。真实反例为[60,75)的GT2旧快照125.2075521 kW，经同钟原`gt_floor_local_correction`变为125.750528 kW；原固定物理约束对后者求解，未改变物理容量或新增上层命令权限。

原外部auditor02的112次只读审计实际80完成、32未知，其错误断言与全部日志保留。新外部03只对上界取证修正：用原`source_start_gt_kW/source_end_gt_kW`、有效setpoint别名、同钟合法floor/interlock链和有限下降请求/终点验证执行路径；每台GT取两个独立记录端点的较大值作宽松上界，加原GRID/DG有效许可上界。实际`action`只校验固定/线性段平均和原许可，不反向构造上界。旧快照另列，缺证据或字段矛盾必须拒绝；原冷路径数学、同窗库存能源界和比较容差不变。新版本是否通过以真实112新收据为准。

该电端上界仅属于**这条已执行路径**，不是所有合法控制历史的硬件能力界，也不是证明命令到达就已成功供能。其必要功率违反只能说明当前执行组合不够；不能与共享塔物理下界或同初态有限能源界混称普遍必败证书。全部轨迹仍使用冻结4dfe物理核心，修正外部审计不产生新轨迹、求解或未来信息控制。

## 硬件选择与报告

H1 的功率和能量以已登记关键电请求与共同接续时间推算，并公开效率及上取整规则；临床增幅或实际转接延长可能使“最小桥接”不足，不能事后把容量扩到刚好消除所有失败。

H2 只根据基础结果确认的实际主要瓶颈选择一次。若共享散热断点造成冷服务缺口，则有限蓄冷是有边界的短时旁路，不是永久独立冷源。报告其可减少的初始/持续缺冷、耗尽后的回落和回充代价，C 与 A 同时比较。没有投资价格来源，不给虚构经济回收期。
