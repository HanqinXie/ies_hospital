# V21 预实验数值与日志修复

## 原始失败保留

`pilot20` 的20次尝试因导出契约缺身份字段，在物理开始前失败，原日志保持不变。`pilot20_r2` 修复身份后实际进入物理计算，在允许传播的同一背景中 C/A 均于75 min失败，留下有效前段75 min和未知尾段285 min。未用零值补齐尾段，也未把未知当无缺口。

真实 C 再次运行并以只读 LayerCollector 捕获最后四层，保存原稀疏矩阵、原/求解域行、变量界、目标、整数性、锁、原始解和 SHA。该捕获仍真实重现失败；不是修改输入后另挑一个容易案例。

## 可行性与尺度首因

rank0–2已接受见证在失败rank3的原域中仍可行，最大物理违约约5.68e−14，锁违约0；因此不能将本次失败称为容量或物理无解。失败rank3两次Gurobi都返回最优状态，随后严格原单位验证拒绝：热泵依赖行残差约1.20e−5/1.07e−5 kW，大于原1e−7阈值。锁、整数和能量平衡没有对应矛盾。

原热泵功率约0.0023–0.0034 kW，原热服务关系 `unmet_h+(D_h/A_pump)*x_pump≥D_h` 的系数约13014.6。等价正行缩放会把求解空间的微小误差放大回原kW单位。

修复采用严格等价的变量变换 `x_aux=A_aux*u_aux`。u为无量纲实际供电比例，上界为当时可用比例；电分解行用A作系数，热/冷依赖行用D作系数，公开辅助电交付仍乘回A并以kW输出。零请求固定零，不除零；降额时按required A缩放，不能误用降额后的upper。共同实际求解和所有规划副本一起修改。

独立exact NPZ回放保持全部原约束、目标、锁和容差，两种求解配置映回原域后都通过严格验证，最大违约约5.68e−14，目标与原域独立精确求解相同。另用256组纯域比较覆盖0/.5/1可用度、零及极小请求，行活动差不超过约1.14e−13。

为避免fraction界的1e−7误差被功率A放大，另在每个接受的实际/规划层产生锁之前及最终命令整理之后，明确验证映回原kW的辅助变量上下界，仍使用原1e−7 kW。失败保留backend证据并抛出异常，不剪裁见证。电热冷物理行、原优先锁、整数性和设备容量未放宽。

真实90 min C19回归先在旧源复现75 min失败，再在修复隔离树通过；完整四类×五方案仍须在新冻结中复跑。不能仅凭数学回放或短回归宣布正式门槛通过。

## 日志性能

真实C轨迹gzip约11.79 MB，但展开约266.17 MB；其中约97%是逐层 `validation.rows`，约80.7万条行残差。没有证据据此称GC泄漏。原逐JSON片段调用gzip.write约4355万次，仅序列化约59.7 s；1 MiB缓冲约20.8 s，解压JSON逐字节一致，不改变日志内容或物理计算。

为降低常驻内存，将成功层的完整残差流式写入同一attempt专属gzip JSONL。主轨迹保留每层的汇总、原始解、接受/拒绝记录、worst rows、record ID、行数和规范JSON SHA；失败/未知层仍保留完整内联残差。独立sidecar含每一条原行，关闭后记录文件SHA、字节数、条数和异常状态。恢复工具可还原原导出JSON语义；不是删除大体积证据。

真实C全160个solver calls的离线回放写出1445条记录、807350行，写入约7.59 s，sidecar约9.56 MB，内联调用约15.34 MB。所有原调用对象前后SHA不变，逐调用完整还原的JSON字节SHA相同。以上为日志基准，不冒充新模型完整轨迹资源结果；新物理批次仍需实测。

旧源、失败raw、exact snapshot、原writer与缓冲writer基准、sidecar重建证据分别保存在E盘。本修复使用独立Git工作树，正在运行的旧pilot源保持冻结，不能混用旧/新结果。
