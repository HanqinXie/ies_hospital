# V22 模型变更与迁移

从 V21 分支 `sci-v21-engineering` 的 `298ec4a` 建立本地 `sci-v22-model-closure`。旧工作树、输入、旧结果和失败证据保留。新身份为 `M22_model_closure` / `hospital_ies.model_closure.v22.v1`；本轮没有论文、图件、归档包装、主分支合并或远程发布。

| 原问题 | 最小实现与影响范围 |
|---|---|
| DG已经有能力，免费UPS仍为省燃料耗空 | 新增当前桥接库存目标及服务之后的库存优先层，不用大费用权重。当前P0/P1仍可耗用低于目标的库存；P2/P3与备用、燃料之间的取舍显式保留。上层/执行共用端口；只按实际子区间积分记账。 |
| GRID健康但部分塔/冷机不足时储冷被排除 | 当前held-port无储冷试探决定冷模式，保留少量互斥模式。真实缺冷可放冷；泵/风机/实际电源仍限制交付。余冷回充在全部服务锁定后，增加共同库存滞回。 |
| 锅炉与GT启动没有闭合站电 | 同一电平衡单列锅炉运行/重启、GT AC starter；站母线来源排除建筑UPS。实际供电才能推进时钟，锅炉需连续复归，GT启动不能信用自身未来产电。专用DC资格与建筑UPS分开，有限窗口/次数单列。 |
| 上层整步预算限制新到达的DG当前许可 | 当前witness采用原功率和实际机械/连接能力，持续准备仍受预算约束；原轴功、电功、损失、转子、耗尽事件细分保留。不增加功率或能量，不承诺总持续时间增加。 |
| 单次GT floor联合候选失败被当作全部不可行 | M22最多7个合法非空子集的事务性试探，原ramp/dwell/许可/无倒送约束不动。保留原确无消纳须退出的负例，不新增弃电口。 |
| A的ready标志不够 | 新当前非DG实际电/热/冷及辅机见证，排除pending产能；已观察经过240min才能按原规则放松参考。条件见证不等于未来连续路径保证。 |
| 并网/接续试探读取缓存物理状态 | 继承试探临时编译即时站电、锅炉与库存端口，并在返回/异常时恢复普通配置；失败候选不推进库存、启动或转子。单个held候选不可行不提前终止全部普通命令/联锁处理。 |
| 零蒸汽命令仍被上层算作固定/重启电负荷 | 在实际命令非负投影后校验零命令真值；新命令对应的实际见证应同时关闭锅炉固定电与重启电，held副本仍按旧到达许可。首次假消纳候选保留，独立零命令域完整重解原全部优先层一次；无合法零域时明确给出有限编译域错误及正命令域未搜索边界。保持正蒸汽连续域、原设备阈值和原动作权限。 |
| 代理压力被写作真实过载 | 默认隔离未校准代理及其软偏好；真实硬容量、联锁与依赖保持。显式假设敏感分支使用原1.05/15min，不为增加trip降低阈值。 |
| 辅机归属改变故障拓扑 | 新纯构造接口区分归属重分配与真实耗电增量；故障设计列/权重冻结。合法.75/1.25泵权重逐小时守恒；非法风机份额运行前拒绝。 |
| 温度缺少带符号净显热与有账恢复 | 新纯1R1C状态接口，恢复请求不提交状态，实际额外冷量才扣热库存，被动换热独立积分。原配对SQL按真实Hourly净显热回放，不伪造10min加热。一次有界fit未通过，不部署；另有3区间真实平衡耦合的恢复能量诊断。 |
| 微小ENS左右选策 | 保留原值与原失效/物理容差，新增独立工程等价比较。六关键载能分量及各中断/最长/恢复分别判断，不跨载能抵销；服务等价后才看一般服务及费用/终点库存、同边界条件CO2。 |

共同核心仍是既有执行链的有界扩展，未重写全包。共享 `physical_balance.py` / `sci_engineering/planner.py` 的新行由 `_model_closure_v22` 显式上下文激活；`essential_fixes/execution.py` 的子集校正仅用于新适配器。无新上下文的V21数学与接口继续受原回归约束。

## 公共接口和日志

原 `reset(scenario=..., seed=...)`、`step`、4×3 `service_request_ledger`、`m21_storage` receipt保留。新调用从 `tools.model_closure_v22.environment` 导入 `OperatingHospitalIESEnv/decision_snapshot/run_episode`，从同版本 `policy` 导入 `SciPolicy`；构造显式model_id并使用 `model_closure_v22` 配置段。不把新model_id混入旧V21结果。

新增 `model_closure_events` 只由发生器/执行层持有并细分实际区间；控制快照只有已发生后的当前availability、有限资格、实际启动进度与当前见证，不能读取未来事件表。原四类的历史native parser标签映射保留，在recipe中同时记录canonical_class，不能按文件名误判研究类别。

`action`新增锅炉、GT启动、锅炉复归、恢复风机/泵/冷量等实际端口。`m22_station`记录本段之前ready、本段实际电量对应功率和重启/运行/未供电分类；原 `m21_storage` 逐段保留初末库存、充入、放出、自损、转换损失与残差。`m22_mode_selection`的候选次数不是实际轨迹次数，试探不扣账。

充分电源下的UPS用途另经真实轨迹修正：全部当前服务及已持定锅炉连续性之后，先最小化必要UPS放电，再回充、恢复及费用。这样库存改善来自实际余源回充，当前服务收益仍可使用库存。原中间版本40→38.102→40kWh的约1.75min往返循环及失败试验完整保留在 `E:/hospital_ies_v22_20261025/ups_cycle_fix`；单独组件隔离对照与完整旧源重放分开标记。

新验证入口保留失败及可回收实际前缀；缺字段/未知尾段不填0。每次输出不可覆盖，包含CASE、RESOLVED_CASE、INVOCATION、RESULT、原日志、gzip原生轨迹及PROCESS。状态/attempt、历史参照与新模型结果分开；全程数值仅在完整实际支持上报告。

具体参数、选择次序及适用边界见 [增量假设](ASSUMPTIONS_AND_SELECTION.md)，原始问题分类见 [ISSUES.md](ISSUES.md)。实际验证数值与仍未通过项以 `MODEL_VALIDATION_REPORT.md` 为准，不能用本说明的实现清单代替运行结果。
