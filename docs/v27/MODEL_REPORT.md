## 默认规则究竟改变了什么

公开入口为`python -B -m tools.model_review_v27.validation`。默认新C身份`C_reliability_then_cost_v27`，`online_GT_count_order=after_cost`。显式`--objective-order legacy_before_cost`保留旧取舍与独立身份；旧M25路由缺省也仍为legacy。`legacy_C19_order=True`只保留原准备/备用目标群的相对顺序，不会把新在线台数层搬回费用前。

同一F90检查中，A0在线台数在rank32、最优0、锁上界1e−7，费用rank34；A1费用rank33、最优8.548145 USD/步，在线台数rank34、最优2。其他26个费用前目标及锁容差相同。新顺序保留原1e−5 USD/步费用等价带，不是另放宽物理约束。静态计划差与真实费用分别保存；静态A1计划出力125.750528/0/125.750528kW只是条件命令端点，不能计作OFF机组当下实供。

实际优先顺序应表述为：当前服务及既定服务锁、登记的启动/桥接/备用/准备与调节一致性软目标，随后原货币费用，再以台数/连续性消除多解。不是所有费用前目标都是硬安全，也不是无条件经济最优。[Gurobi分层目标说明](https://docs.gurobi.com/projects/optimizer/en/current/features/multiobjective.html)只解释后层受前层锁约束的数学语义；本项目仍使用显式逐层求解加锁，没有改成新算法或滚动控制。

- `regulator_GT_excess`：在原GRID/local-down契约下偏好命令GT接近原最低稳定出力，配合实际卸载及HRSG/ABS耦合的准备副本；不是设备硬上限，其额外词典序独立收益未证明。
- `standby_third_GT_exposure`：惩罚超过两台的命令暴露，0/1/2台同值。是登记的软备用安排，不证明健康N−1、旋转或即时可达备用。
- `normal_online_GT_count_after_preparation`：全部命令在线台数，没有额外物理/备用依据，故移到费用后。不能与前两项混为一谈。

完整层级、工程意义、量纲、激活条件、锁容差和来源见`objective_order/INHERITED_F90_OBJECTIVE_HIERARCHY.csv`、`objective_order/RETAINED_PRE_COST_TARGETS_ZH.md`。采用的A0/A1静态分支均从母快照独立fork并重建求解，未携带A0台数锁；母快照与真实物理投影不变、时间不推进。真实续跑不reset。A1容器顶层policy_id表示续跑上下文，0–90min实际仍为共同legacy前缀，逐决策policy_diagnostic保留真来源；不得把这条分叉当成全时域after_cost策略样本。

## 年度冷需求来源已经找回，但不等于物理真实性认证

本轮找到原Starter目录中真实年度工程派生26.2 IDF、submeters派生、两份原SQL、天气、修复记录与提取器，并核对原provenance SHA。它们不同于原22.1 IDF。以只读URI实际重新导出四份负荷CSV，逐字节相同于原输入；候选单列，未覆盖原28输入。年度八盘管总冷3324738.363451484kWh，原年度Hourly盘管值负值计数0，独立求和对原输入最大差约4.55e−13kW。

来源链为：真实派生IDF/天气/求解设置→八个`Cooling Coil Total Cooling Rate`（W，Hourly Avg，总冷含潜热）→按原标准时小时→8760总冷→14关键区显冷代理与原分级。蒸发器产冷不再加一次需求。区域显冷为代表区，倍率乘一次；电表及实际再热部件输出按其原含组倍率定义处理。既有区热/冷代理裁负、比例压缩及P3剩余逻辑公开，本次条件映射若产生负需求或代理超总则拒绝，没有静默裁零。

原年度SQL只保存Hourly，不能事后恢复未存储的年度真实系统子步。有限两条正常SQL则可与API按真实子步跨标准时小时积分逐盘管核对。SQL的Year为2017，API/参考另有2006报告标签；相关月日星期对应一致，夏令时报告钟与标准时另行区分，不能只凭年份不同认定错位。有限7月18–22日从新RunPeriod初始化，与全年同日此前热历史不同。两条有限原/Min8绝对曲线均不作为年度修正真值。[EnergyPlus 26.2仿真参数说明](https://energyplus.readthedocs.io/en/v26.2.0/guides/input-output-reference/1.5-group-simulation-parameters.html)用于区分区域/系统时步、迭代与初始化；实际时间对应仍以本次SQL/API证据为准。

原SQL两个完成标志为FALSE，但`.end/.err`写运行成功、0 severe，矛盾未解释。199个Warning文字标记不等于199次警告：44类recurring累计22,832,385，加147次非recurring，合计22,832,532；主要为热水供温约束22,035,882、冷机曲线域761,362、塔曲线域35,141。完整错误日志、统计与限制随包。输出完整、哈希相同和重提取一致，均不能洗去这些物理/来源资格限制。

完成轨迹不等于所有候选求解都成功：新四主案5214 backend尝试中4980通过、42个原域拒绝后重试、192个不可行候选均保留；无实际物理求解错误或策略回退。敏感性各例拒绝尝试190/178/72/72，包含不可行探针及最优状态但原归一化锁校验拒绝后再接受的呈现；未扩大原容差。实际fixed_execution全部成功，timeout、策略/投影fallback、原solver_errors均为0。触顶、费用、服务和启动均据原生实际过程验收，未用测试数/哈希代替。
