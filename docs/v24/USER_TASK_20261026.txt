请追溯原始容量来源和本研究约定，明确：
1. 名义冷却塔吨、制冷吨与实际kW排热上限的区别；
2. 设计湿球温度、进出水温差/流量或实际额定排热依据；
3. 目前4219kW究竟是有依据的研究假设，还是单位换算混用。

同时核清实际进入冷凝水回路的热量边界。现有EC 0.77kWe/RT是包含部分泵/塔风机的总耗电系数；若新增回路温度动态，不能未经区分把全部综合电耗都当压缩机向水侧排热，也不能重复增加已计辅机电。静态聚合近似可以声明，但动态传播不能建立在互相矛盾的热流口径上。

四、让L2检验有依据的故障传播

当前实际事实：
- 匹配L1/L2的177个实际区间、实际前缀和过程表相同，关闭旧research_stress_proxy后标签本身不改变物理。
- 共同模型已有设备/供电/流动依赖；锅炉也已有连续付电复归状态。不能说全无保护或恢复动态。
- 该配对没有激活新的传播链。部分L1配方仍留canonical_class=L2，是元数据一致性问题；修正标签本身不用重跑物理。
- RestartState通用接口有flow_available，不等于生产调用已接入全部流动条件。梳理时以真正传入的源、硬件、到达许可和实际状态为准。

先使用现有共同物理机制寻找有意义的传播工况。如果已有机制能够产生二次功能退出及恢复，优先使用，不为复杂而新增状态。区分外生初始故障、即时功能依赖、二次保护退出/锁定、正常调度停机和永久损坏。

现有机制不足时，授权补一条最小而可检验的工程传播链。可优先评估：
共享冷却环节能力下降 → 实际排热积累或流动条件失效 → 冷机限载/保护退出 → 下游服务受损 → 条件恢复后复归。

如果用聚合回路温度：
C_loop × dT_loop/dt = 实际进入回路热量 − 实际散热量。
统一kW、kWh/K及时间单位；状态只由实际热流推进。必要参数来自现有IDF、设计流量或设备资料，缺测量时使用透明受限的研究范围。
已有physical_balance中的tower.rejection瞬时上限必须与新动态假设协调：不能一边强制所有时刻Q进≤Q出，一边虚构正热积累。也不能凭空允许超过设备温压边界的运行。

规则：
- 不恢复“未供需求+GT实际功率=过流”的旧代理；
- L1/L2/L3/L4和所有策略采用同一依赖/保护规则；
- 将L2定义为预先登记、具有传播条件的扰动；策略避免了传播，仍属于该预定工况，不按最终结果重新分类；
- 保留原同条件换标签的等价过程作为负对照；
- 原厂资料支持机制存在，不证明医院型号和阈值。不得抄阈值后冒充标定；
- 不为了必然看到跳机而关闭正常限载/本地保护。可避免与不可避免的传播都允许出现；
- 新模块关闭/开启属于物理机制敏感性，不能作为同物理策略优劣。

最小验收覆盖正常/短扰动不触发、足够扰动按真实状态触发、合法运行安排可避免或延迟的情形（若物理上可能）、条件恢复后复归，以及仅换类别标签不改实际结果。记录因果顺序、实际触发量、能量账、保护与恢复条件即可，不发展庞大的事件归因系统。

若资料确实不足，具体说明缺哪个参数、它限制什么结论；完成其他工作，不伪造传播，也不通过删除L2目标宣布全部完成。

2. 冷却塔部分故障C/M对照中，M可在服务等效下少费但增加CO2；费用优先的比较选择不等于各维度支配。正常夏季C/R的费用差仅0.005106069 USD、条件CO2差0.013490108kg，不包装成显著工程进步。
3. 允许并行分工：蓄冷及共同核心由一个写者负责，温度诊断/参数来源/结果核验可独立；验证时保持源稳定。
4. 授权进行必要接口整理、删除重复内部实现或局部方法替换，但保留历史入口/结果身份与足够回归。不要仅增加包装层让调用链更难追溯。
5. 每次扩大计算说明要解决哪个仍未确定的问题。先最小反例/正例，再受影响完整过程，最后一次集中回归。不要把新增测试数、attempt数、哈希层数、包体积当成果。
6. 仅改报告、日志压缩、标签元数据或包装时，不反复重算全部物理过程；共同物理或策略目标变化时，按真实影响更新比较。
7. 不自动push、不合并main、不远程发布。常规可逆实现、合理研究参数范围、补充资料、必要计算和小包交付已经授权；确需不可替代输入时先完成不受影响部分，再准确说明所缺内容。
