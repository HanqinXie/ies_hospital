# V24 医院 IES 工程模型报告

本轮接续本地 V23，而非较旧远程 main。保留原28项输入、DOE/IDF/8760负荷、P0–P3服务判据、原设备边界、命令队列和真实接续时钟；没有MPC、预测器、未来故障或真实修复终点输入。排放仅作事后评价。任务不包含论文和制图。

## 供能与保障的工程含义

关键区域的电、热、冷需要沿实际通路到达。上游有冷量不能替代房间风机，冷库有库存不能绕过水泵；建筑UPS也不能替代厂站非UPS供电和锅炉复归支路。可用能源、瞬时功率、路径、到达许可与启动/转供时间分别构成瓶颈。本轮以实际区间积分和真实状态判断这些限制，而不是以“控制可用”推定服务已恢复。

### 1. 蓄冷的付费回充、实际交付与正常库存

修复了“关键冷需求仍有缺口即预选放冷/空库idle”的遗漏：若缺口源于房间风机不可达，但上游制冷、塔、充冷泵、源电和已到达许可正常，可以在不牺牲原当前服务的条件下付费回充。空库和部分库存均核验，负例包括无源、无泵及无到达许可。

生产Gurobi和实际推进的小反例：P0电20kW、冷100kW，风机失效、泵正常，GRID上限100kW、EC上限100kW，GT/DG/锅炉/ABS为0。新增合法模式实际充冷100kW，GRID为38.894573kW，另有真实冷库泵2kW；1min后增加库存1.583333kWh。随后风机恢复、冷源中断时，该库存可实际供100kW约54.15s，仍支付泵电。后续事故只用于离线验证，未告诉在线策略。这是原物理矩阵中的合法域遗漏，绝非发现免费能量。

所有候选读取同一快照；试算不推进库存、时钟或启动次数，最后仅执行选中动作一次。原目标仍为每等级内归一化电/热/冷缺供合计。新增charge域有保守逐载体服务上界，不能借原费用层允许的服务锁微量退让充能。若idle等no-charge域确实均不合法，允许以charge自己的严格原服务见证证明真实固定源消纳域；近满维护滞回的必要消纳例外显式记录，不越过容量、功率、效率或许可。

首批Source01完整过程又暴露一个新问题：健康期9次放冷均未改善原任何非费用目标，仅因当步费用较低获选，随后触发维护回充；15min库存从60降至58.7516923233kWh。八次完整回满及末次部分回充的原行与候选均保留，不能把能量对账正确当成运行模式合理。Source02增加仅费用驱动放冷的准入限制，原全部非费用目标顺序和锁带保持不变，有益服务/启动/桥接/恢复及原UPS目标收益仍可保留；不改变容量与事故。修后C/M两条完整过程的健康0–15min均充放为0，库存59.8501873438kWh仅有原自损耗；部分塔故障下首次真实耗尽为57.9355338710min。最终独立小表使用这些新实际结果，不以首批冷库数值替代。

180min风机故障—上游付费回充—风机恢复/冷源中断—重复故障完整过程，M24实际充入150.000000kWh、交付107.642174477kWh、末库28.466776745kWh。耗尽后[87.491234243,90]和[164.338544997,165]区间实际充放均为0，原5.66e−15/1.67e−14库存残值保留，没有删库存或合并区间掩盖微脉冲。本例Source02重算后的182区间实际动作、服务、库存与费用恰与Source01 M24相同：新准入不意味着每个过程都必须变好。

同事故、C策略、硬件和时钟的legacy M23运行作实现反事实；M24相对它的P0/P1冷ENS分别少52.929815858/35.229985797kWh，但GRID多24.761661551kWh、费用多2.101446368USD、CO2多4.812379408kg，末库相同。新增电量有EC与真实泵电来源；不能将改善说成免费或策略全面支配。两边分别保留真实Source01 legacy与Source02 M24源码，这是跨版本修复诊断，不混入同模型策略排名。

### 2. 冷却塔采用独立研究kW，未擅自增容

默认排热上限保留4220.223408kW，即原4×1200×0.25×3.51685284。它现为独立显式参数。原医院材料仅说明four1200-ton towers，缺塔吨定义、设计湿球、进出水温和流量，不能认证为医院真实额定排热能力。

制冷吨12000BTU/h与名义冷却塔吨15000BTU/h不同；5275.27926kW只作为后一口径下的单位歧义边界，进行一项同背景对照。没有把资料不足写成已确认换算错误，也没有把边界对照称作实际医院增加25%能力。[Delta官方说明](https://deltacooling.com/resources/faqs/selecting-sizing)给出单位与设计条件关系，不是医院铭牌证明。

修后该边界对照使P0冷ENS减少2.461685239kWh、一般区冷ENS减少6.193794908kWh，费用增加0.166406995USD；P1冷ENS仍在原工程带内相同，关键工程联合最长中断仍为17.064466129min。提高假设排热能力改善部分交付，却未解除这个最长保障瓶颈，不能把单位边界写成全面解决方案。

EC的0.77kWe/RT包含部分冷凝泵和塔风机，仍按原综合电量付费一次。保留静态聚合排热近似，不能把全部电耗认作实测压缩机水侧热量。未新增回路温度动态；也未在每刻排热受限的同时虚构正热积累。两份Trane资料仅支持保护机制存在，不提供本医院阈值或型号标定。

### 3. L2使用真实有限能源链，并保留不利转供结果

无需新建未经标定的冷凝水动态：已有实际链足以检验上游断供→DG有限轴功预算消耗→非UPS实际总源归零→锅炉功能/复归资格失效及保护锁→真实源接续→连续付电复归→重新供热。所有类别和策略共用同一机制；L2是事先登记的传播条件，不按是否最终触发重新分类。仅换L1/L2标签的匹配过程实际一致。

长扰动、150kWh轴功预算：GRID在60min失去，原在线GT2桥接；DG于75min接入，90min失去其余GT。DG在153.6728342258min实际耗尽，总轴功扣账150kWh。此前锅炉有正蒸汽和辅机电，此后总源和蒸汽为0；ready失效/锁定在165min状态结算可见，不能把观测结算时刻倒写成厂家跳机时刻。GRID实际于210.5min回来，0.5kW复归电持续1min，211.5min恢复ready与蒸汽；60s热服务确认另到212.5min，不增加ENS。

短扰动同150kWh未耗尽，终点尚余6.1840257067kWh，因此是耗尽传播的负例；但150.25–150.5min真实转供OPEN仍造成0.25min无源，并独立引起锅炉短时功能退出/复归。它不是“任何保护退出都没有”的理想负例。正常工况为纯不触发对照，不能改事故或放松阈值消去这个不利发现。

同一长事故增加到300kWh时，控制器仍按真实等待接续，DG到227.783840878min才空；源于228.283840878min接回，229.283840878min恢复蒸汽，关键工程中断最长1.5min。600kWh时GT3于240min真实就绪并可在转供OPEN期间桥接，源未归零，未出现关键工程中断，终点轴功预算262.730659483kWh。该时段锅炉蒸汽为0可由HRSG替代解释、ready仍在，不能误标为保护退出。

本结论是软件模型中由真实源条件驱动的二次功能退出与付费复归，不是永久硬件损坏试验。通用RestartState虽有flow_available，当前锅炉生产调用未接入该项，不能宣称覆盖失流保护。有限DC启动资格不是Ah/CCA电池模型。

### 4. 夏季温度诊断完成，定量恢复精度仍未合格

温度模块默认继续为None，供能排名不使用温度补偿抵销冷ENS。旧双状态9/16通过中，冬季8/8属于弱激励，夏季仅1/8，旧难例未删。原校准夏季OR1六小时事件，从供冷恢复到三点持续入带首点的耗时，EnergyPlus为760min、旧模型1890min，误差1130min；慢模态约98.286h。初态/时轴/单位和正常基线差额未解释尾差。

追加4次原日期正常/六小时派生EnergyPlus输出，严重/致命错误均0，1090项设备尺寸逐项一致，旧热流差不超过5.68e−14。冬季OR1冷通道仍达正常的99.52%，原因有节点和再热输出支持：固定外气/原风量继续、末端再热减少；IDF为NoEconomizer，不能称经济器开启。夏季送风温度升高、再热降到0，与供给丧失相符。OR1六小时冷通道1.436782kWh、热通道0.832128kWh，净H−C为−0.604654kWh；不能把冷通道单称净显冷。

原0.01min HVAC实际子步相对10min输入的六小时积分差约−4.87e−6kWh，尾均温影响约+0.000456℃，不能解释旧尾差约+0.2354℃，因此没有靠更密重采样制造通过。四区域固定参数2R2C仅夏季1/8通过，最后一组受IDF容量约束的空气/家具/墙三状态0/8通过；最大误差约2.11–2.68℃、恢复初段RMSE约0.612–0.679℃，参数触边。全部fit、错误和原门槛保留。

据此结束本轮低阶结构扩展，没有新日期验证、按天参数、真实未来墙温输入或放宽20min恢复门槛。该模块只能用于限定的共享机械盘管关闭干预下的探索与误差诊断，不能定量承诺夏季恢复时间、整AHU/风机失效、供暖失效或临床安全。若要升级，需要能约束末端控制/再热/风量/表面对流与慢热交换的匹配辨识资料，再冻结后做独立强激励检验。

### 5. 资源受控对照显示能量、功率与路径的不同作用

DG150/300/600对照只改初始可用轴功预算，其余长事故、背景、C策略、时钟与权限相同。150→300使关键工程中断57.827165774min降到1.5min，但一般区电/热/冷ENS分别增加约76.9091/12.4261/23.6939kWh，费用增加40.576223733（原2001USD口径），条件CO2增加137.675395285kg。300→600避免关键中断，但费用又增8.731935708、CO2增78.759590015kg。不是所有资源增加都使所有闭环指标单调改善。

UPS能量20/40kWh固定160kW，40kWh下80/160kW功率另列；无UPS作为有无资源锚点。UPS20实际可供19kWh，把P0/P1电ENS从48.001872814/33.480184103降为36.811879315/25.670183495kWh，最长电中断56.8272min降到43.5799min，但热冷仍受非UPS源与设备恢复约束，关键服务联合中断57.8272min没有被消除。初末均20kWh来自实际回充，不能当免费终点补齐；初始准备输入21.052631579kWh、费用1.948631579，含准备总费用比无UPS增加3.497401510。

20→40kWh固定160kW时，P0/P1电ENS仅进一步降为35.117918715/24.487892074kWh，最长电中断41.574494801min，未成比例延长关键供电。原824区间核验说明原因：60–75min在线GT仍供电，20kWh组UPS输出0，40kWh组已输出16.11897224kWh、耗库存16.96732957kWh；三组P0/P1/P2电交付相同，增加主要用于当时P3电及可达热冷。40kWh并未全部保留到非UPS总源归零，改善包含早期真实一般服务，不能只按名义能量除以关键负荷推算保障时长。

同40kWh把功率160降至80kW后，P0电ENS进一步少0.974571987kWh，而P1多同量；P1最长中断由41.574494801增至56.817016896min。功率限制下优先供P0并延长其续航，同时P1较早缺电。这个容量/功率/当前分配的差别与DG耗尽、实际库存和服务原行相符，不是改了事故或服务分类。

冷库能量30/60/90kWh固定120kW，修后关键工程最长中断分别38.493809422/17.064466129/0min，费用分别64.539557246/65.290320595/65.881700905USD，终点库存28.466776745/28.466776745/35.690876474kWh。增加初始可用能量在这个事故中有效，但不能绕过风机/泵路径，初始能量与准备费用另列，不能据相同终点库存认为使用了相同资源。

60kWh下把充放功率从120降到60kW，关键最长中断反而由17.064466129降为3.414704897min，P0/P1冷ENS分别少2.342129572/6.848507077kWh；代价是一般区冷ENS多13.182357593kWh，末库由28.466776745降到14.233388361kWh，费用少0.367768040USD。原瞬时优先级允许有益的一般服务使用当时可用库存；较小功率减少这部分当前交付，延迟后续耗尽，同时限制回充功率。它是相同闭环规则下真实的服务分配/续航权衡，不是较小功率扩大了物理可行域，也不支持所有指标随资源单调变化。

### 6. 应冻结的部分与仍需资料的部分

默认供能核心在本轮有界研究范围内可交付：真实模式、有限库存、付费充放、实际路径与接续过程可对账；这不等于所有医院物理已验证。既有有限源链的传播/复归检验可交付，同时保留短OPEN和未接入流动条件的限制。温度偏差诊断完成而定量模型未合格，结束本轮扩展并保留显式探索配置。

冻结本轮有效核心、原判据、已成立边界和实际失败记录。后续确需资料包括医院冷却塔设计额定条件、设备流动/保护与恢复参数，以及对应失供干预的热动态辨识数据；不得用本轮会计一致或测试通过替代这些证据。
