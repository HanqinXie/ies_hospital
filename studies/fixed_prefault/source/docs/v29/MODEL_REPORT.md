# V29 同版本机制验收与模型定版

当前模型可用于给定原型医院、P0–P3服务分组及既定设备条件下的中央IES故障接替、功能依赖、有限库存与服务缺口研究。本轮七条新增主轨迹及三组匹配核验通过，复用V28 B_N/D/FD三条实际证据；在这一声明范围内，未发现仍须修复的物理/实现错误，**建议模型定版**。这不构成实院、全年容量或温湿度/洁净度认证。

## 医院怎样接续，哪些服务保不住

### 外网退出：关键服务保持，一般服务付出代价

继承冬季h211、360min工况，H1为原登记40kWh/160kW UPS，设备与事件不变。故障前只有GT1实际供电132.26624kW，GT2/3停机，DG为OFF；停机名牌余量没有被当作即时备用。

外网60min退出后实际购电为0。45min已经到达的条件权限使DG在60min本地进入STARTING，60min新命令直到75min才到达；DG到75min才有端电正出力。条件许可、命令到达、启动和实际供能分别核对，没有提前供电。

UPS有用放电16.210008kWh，充电输入17.961228kWh，最低库存22.940997kWh，末端回到40kWh；末端满电不代表从未使用。DG轴功预算消耗213.755335kWh、端电179.624204kWh，预算2400→2186.244665kWh。轨迹积分端电/轴功比约0.840326，不能把轴功预算称为端电或柴油化学能。DG启动DC实际kWh未建账，保持null；继承的2次合格启动/1440min控制自主资格是研究假设，本次用了1次，不是OEM电池认证。

P0/P1没有达到原工程判据的中断，恢复时间为不适用。P3电60–195min不足135min，ENS92.266146kWh；P3热/冷71–75min不足，ENS分别2.362367/0.428705kWh。外网可用率180min恢复，随后RETURN_PREP到180.25、TRANSFER_OPEN到180.5，180.5才实际重新购电；P3电到195min才恢复。不能把“关键保持”“网可用”“实际并回”“一般服务恢复”合并成一个时刻。

### 共用冷却塔：有电也不能绕过共享排热瓶颈

继承夏季h4001、90min工况及原H2蓄冷60kWh/120kW。正常对照中ABS301.032382kW、EC199.465510kW，塔实际排热1044.913017kW，目标设施确实承担功能。15–75min仅TOWER可用率降至0.01，沿原共享排热约束同时限制ABS/EC，原冷请求没有缩小。

蓄冷从15min实际放冷79.164878kW，第57.935534min耗至0，累计有用放冷56.649772kWh。P3冷从15min便不足；耗尽后P0/P1关键冷服务中断17.064466min。全案冷ENS367.595512kWh，其中P0/P1/P2/P3分别2.897757/8.550082/9.281258/346.866414kWh。

塔75min恢复后关键冷服务当刻恢复，76min按原规则确认。GT1此时仍在75–85min启动，支付10kW AC共1.666667kWh，85min才正出力，不能把它说成75min恢复的原因。启动电由当时实际电网与已运行GT的共同厂站母线支付，建筑UPS不是该启动AC源。75min后充冷输入约30kWh，末端库存28.466777kWh，未假称充满。

这是单个共用设施造成的多路径功能传播，没有新的设备损坏或保护跳闸。更多电网余量或多开GT不能消除已经登记的共享排热上限；本轮没有改容量/保护阈值去制造成功。

### 热循环泵：采用新热输入后仍会中断

H0无UPS/蓄冷，继承h211、180min及60–120min热循环泵可用率0.5，补做了采用版N/F。关键热中断60min，120min实际恢复、121min确认。热ENS合计**73.709162kWh**，P0/P1/P3分别17.977634/18.171671/37.559857kWh。该新结果不能用旧A_original_heat的73.535403kWh改名替代；泵—服务关系仍是声明过的比例代理，并非实测水力定律。

## 本轮真正覆盖的机制与证据复用

L1由外网退出/接续及泵局部故障覆盖；L2由共用塔对ABS/EC的功能传播覆盖。V28 B_D确为无硬件故障的急诊四区各25%增长，B_FD为活跃GT2故障与同一局部需求叠加，分别提供L3/L4证据。原内部parser标签不替代研究分类；GT退出→HRSG蒸汽减少→ABS下降→EC/电网接替本来就是有效功能传播。没有发生的二次损坏或保护退出不补写。

复用三例绑定V28 producer09f92284、source9cb3ea82、input5c6fea46与H0。本轮producer8926dfb7、sourceec2a2e8c、inputf414d21f是新入口/注册/质量标记的版本；836项原科学文件逐字节不变，原pytest.ini仅追加两份测试，33旧输入全保持。新增3输入只是源冷质量原行、55区筛查和元数据，没有改负荷。没有实现新控制算法、MPC、ML、拟合或温度模型。

三组N/F完整物理初态/core及故障前合法历史、队列、数值命令一致。全局RNG诊断不同原样保留；逐叶计时差异仅限定在明确的elapsed_seconds、TimeLimit、remaining_original_budget_seconds，未过滤真实命令或物理值。本次固定路线没有使用未来故障/真实恢复真值；不是全项目任意算法的信息流形式证明。

条件transfer_300 N/F已注册但未运行：网例已实际验证DG启动、端电和预算消耗；本轮不保留“柴油耗尽/离网自持多久”的主张，因此不为凑数派发复合例或150/600矩阵。UPS未耗尽，DG剩余充足；有限库存的实际耗尽边界来自H2蓄冷，不能互相替代。

## 来源、验证与定版边界

源冷26条zone-hour原行、25个唯一小时、55区筛查及9.5zone·h均保留，所有正式/复用窗口与其无交集。每条结果和SOURCE_SCOPE.json自动标记计划/实际时段，仍明确使用源盘管交付代理；半小时交集不按比例伪造未满足时长。Laundry来源燃气、Booster已计入直接电的来源电分别单列；60℃上游预热来源能源/费用/CO₂保持null，不加入中央实际账当免费热源。

实际默认测试：**1320 passed，0 skipped，431.20s，退出0**。当次SCI_SOURCE_ROOT仅为可选原源SQL只读检查，执行前已捕获选定环境；干净公开入口与便携原生复算不需旧SQL。七例独立原生核算通过，后台51457次尝试中918次未接受，全部原始指针/元数据保留；无策略/投影回退、无超时、主物理失败0、未知尾0。早期RED、smoke登记修正、CRLF冻结预检及审计枚举差异保留，未改旧断言或放宽数值容差。

详细账在native_audit/final01及interpretation01，机制表见MECHANISM_COVERAGE.csv，范围见ASSUMPTIONS.md。公开入口/便携只读重放和最终ZIP独立解压以各实际命令记录验收，不拿本页声明代替后验。
