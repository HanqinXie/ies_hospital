## 共同准备与 U 的生命周期

共同故障前环境负责准备同一合法连续状态。共同准备可以包含原有正常工况优化，但其优化调用、输入、状态和版本必须单列记录，不能记为 U 的零优化执行证据。

公开入口包括 `finish_common_prefault_step(common_env, action)` 与 `fork_fixed_unattended(common_env)`。共同环境先按原方法推进到第 59 分钟，再用前者完成 59→60 的实际区间，同时暂停尚未施加的第 60 分钟故障/旧命令边界。该入口仅接受普通/响应共同环境和一分钟步长，写入边界暂停标记；普通 `step` 完成到 60 分钟的环境不等价于这一检查点。

随后 `fork_fixed_unattended(common_env)` 校验第 60 分钟暂停标记、最后实际区间结束时刻和冷却动态，从活状态深复制出独立 U，并安装冻结份额和严格禁优化契约。U 的第一个实际步在自己的环境中执行原第 60 分钟边界，再结算故障后区间。不允许从事后轨迹或未来响应组结果反推初态。深复制范围包括已执行端口、库存、故障和保护状态、排队命令、启动/恢复时钟及冷却动态；完整状态范围仍需真实运行核对，不能仅凭时间标记代替。

新 U 的公开 `reset` 必须明确拒绝，不能在 U 内部再次调用正常工况初始化优化。U 从检查点启动直到结束，实际流、保护探测、诊断、评价和状态快照路径均禁止任何优化入口，不再依赖旧 `t>=60 min` 条件才禁用。共同准备记录与 U 执行记录有明确角色和边界。

深复制后的可变状态不得与共同环境或响应分支共享；推进任一分支不得改变另一分支的库存、队列、历史、保护时钟或冻结份额。`checkpoint.py` 除深复制对象外，还重绑定环境工厂闭包捕获的旧 bound method，避免复制后的 `step` 仍操作共同原对象。复制失败或缺少冻结所需端口证据时显式报错，不能使用全零、均分、当前需求比例或优化结果作为隐式替代。

## 冻结份额及不足分配

份额只从共同检查点之前最后一个已结算实际区间获取。各载能建筑支路、一般电力中的建筑支路与机房支路，分别保存原始实际端口量、归一化分母、份额、区间时刻和来源。建筑电力中直接用电与风机/泵等辅机的原有端口关系继续记录，不能把辅机电力额外计入第二次。

对一个固定连接组，令原实际端口量为 `x_i`，冻结份额为 `s_i=x_i/sum(x)`，当前实际可用总量为 `B`，当前可连接需求/设备可达上限为 `r_i`。冻结额度及交付采用：

```text
quota_i = s_i * max(B, 0)
delivered_i = min(max(r_i, 0), quota_i)
unused = max(B, 0) - sum(delivered_i)
```

份额计算一次后保持不变。当前需求下降、支路失效或设备容量降低，只会减少该支路实际使用；其未用额度不能重新分给其他支路。不得重新归一化剩余支路、按 P0–P3 排序、按缺供或费用枚举候选，或先为 P0/P1 预留供能。所有 `unused` 均须进入实际资源闭合、原有保护或合法下调过程，不能当成额外服务或静默消失。

冻结前为零的支路份额保持零；总量为零时该连接组份额全零并保存零分母事实，不得凭空均分或新启。零实际运行参考的备用冷机也不能因其容量尚存而自动获得新的运行目标。已存在的硬件自动启动/切换、原命令和保护作用仍依原权限执行，不能用冻结份额规则增加设备权限。

蒸汽供建筑热与吸收式冷机、冷却塔供各冷源、一般电力供建筑与机房，均按已登记的故障前端口分配关系执行，不允许通过隐含“先保关键服务”步骤绕过冻结份额。物理故障、辅机失电、库存状态、冷却动态和可达容量先约束真实端口；最终服务仍受实际电、热、冷依赖限制。

## 专用源和真实连接

UPS、应急柴油和蓄冷保留原 P0/P1 专用连接范围，不扩展到 P2/P3 或机房辅机。专用源在其原连接集合内部，按检查点最后实际服务/端口形成的冻结比例分流；份额来源和零分母情况同样显式记录，不根据当前需求重新计算权重。不允许先供 P0、再供 P1。

专用连接导致某些服务可得到额外硬件支持，属于原拓扑事实；不能将其描述成新 U 的优先调度。原 ATS/DG 连接、开路转换、燃料耗尽、UPS 和冷库存空满、充放电效率与损耗、辅机供电、保护联锁及响应时间仍须约束实际执行。专用源的能量不得计作普通总线或机房供能，也不得通过一般电力预留人为替它“腾出”能力。

## 命令、保护与数学求根

检查点内已存在的旧命令按原生成时刻、到达时刻、覆盖顺序和执行条件处理。其合法到达可以改变已许可的设备参考或开关状态，但不得重算支路份额或建筑热/ABS 的冻结蒸汽比例，也不得据此生成新调度、瞬时启动备用机或绕过爬坡和启动时钟。U 不生成新的优化命令或服务优先切除命令。对检查点前已经发出的自动切负荷请求，仅在原到达时刻按原固定数量、当前可连接上限执行，不再按 P0–P3 次序产生新请求。

保留真实故障、强制容量降额、原保护阈值与积分、最小稳定出力、无外送联锁及合法恢复。设备保护中的预定执行状态机不能使用 ENS、P0/P1 满供、费用或最大供能候选排序来代替硬件判据；若原接口含这种服务择优，需要在新 U 路径明确迁移并保存原因。

数学物理方程求解及库存/保护事件求根允许保留，但仅用于已固定端口关系下的资源闭合或边界定位，不允许寻优。求解不闭合、动作不可执行、保护拒绝和禁用优化入口尝试必须记录输入、路径、原因与失败前缀，不能填零、静默回退或继续声称完成。

Python 优化入口使用执行期 profile 审计，Gurobi 原生入口另设由 context variable 激活的显式拦截，覆盖 Model 构造、同步/异步优化、可行性放松、IIS、调参和预求解；非 U 上下文仍调用原原生方法。禁优化异常继承 `BaseException`，不能被普通 `except Exception` 回退吞掉；首个尝试将 U 标记为失败，后续受保护执行入口拒绝继续。禁止绕过这一致命错误继续 U，也不能把拒绝记录当作零尝试成功。
