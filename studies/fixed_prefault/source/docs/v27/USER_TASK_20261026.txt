3. 工作 A：运行目标顺序的有限核验与修正
====================

3.1 查明真正运行的顺序
从公开执行入口追踪当前 C 路由，输出一张实际目标层级表。每层列出名称、工程含义、量纲、优先级、锁定容差、当前是否激活、来源配置，以及属于以下哪一类：
— 物理可行性/真实硬安全约束；
— 关键服务可靠性与已登记备用/准备目标；
— 可选运行偏好；
— 货币费用；
— 同费用范围内消除多解的偏好。

不要把所有费用前的软目标都称作硬安全。特别解释 regulator_GT_excess、standby_third_GT_exposure、normal_online_GT_count_after_preparation 的区别。

起始证据在 project/tools/sci_engineering/planner.py：1258–1263 建立少开机目标；1370–1439 安排在费用前；1441 后才有费用近似相同下的启停变化偏好。行号只作定位，按实际源码核实。
F/FD 的 90、105、120 min 中，在线台数层 rank 32、最优 0、lock_upper=1e−7，费用层 rank 34。另一项 normal_commitment_preference 实际 disabled，不能误用它解释这些运行。

3.2 先做单因素、同状态对照
首选 F 的 90 min，因为硬件已经恢复可用，GT 均 OFF、没有待完成启动，并且 DG=0，较容易隔离费用口径。
恢复同一个完整合法状态：设备状态与已完成启动时间、实际启停限制、已到达命令、许可、待处理队列、储能和燃料、备用账、当前负荷、当前故障可见状态、历史观察。不能只复制 PROCESS 中几个功率值冒充完整状态。
如包内不能直接恢复该状态，从原公开入口重放 0–90 min 一次并保存完整快照；核对前缀与原案。控制器不能从快照获得环境隐藏的未来修复计划。

在同一快照上比较：
A0：现行完整目标顺序。
A1：只将 normal_online_GT_count_after_preparation 移到现有费用目标之后；其余上层目标、物理约束、价格和费用向量保持相同。

A1 必须移除由该台数目标产生的锁，再重建求解，不能把 A0 的零台数锁当物理状态继续保留。真实 GT=OFF 的初始状态仍保留，启动后的条件出力不能提前当作现时供能。

第一项对照先不同时重写费用向量，从而能归因。当前费用向量含极小弃汽偏好，DG 计划成本与实际轴功修正有不同口径；先准确称作‘既有费用口径下的条件对照’，不要提前叫纯实际费用最优。

保存每层目标及锁、当前命令、计划出力、真实可执行出力、启动耗电、计划费用及费用组成。若 A0/A1 无差别，给出更早目标或约束的证据；允许合法结论是不启动。必要时追加 105/120 min 或 FD 的少量快照，全部快照对照最多六组，不做搜索。

3.3 按真实过程验证经济含义
对 A0/A1 至少各做一条 90–180 min 实际续跑，采用相同环境实际过程和相同信息规则。不能在中途强制重启，不能把命令发出等于机组立即完成启动。
核对关键服务、真实启动能耗/耗时、燃料和库存、供电/供汽/制冷、所有安全与守恒约束、真实累计能源费用。分开报告计划目标值、实际能源费和微弱优化偏好。
记录初末库存差；如末端库存不同，不把简单总费用差冒充同等终态的长期收益，也不要临时发明库存影子价格。保留原有末端规则，报告实际差异即可。

禁止预设：重启必定更省、累计费用必须下降、少开机层必定是唯一原因。F−N 的故障后费用差仅用于确定核验价值，不能当作可实现节省。

3.4 对默认策略作工程决定
如果少开台数只是可选偏好，没有额外的可靠性依据，则按用户‘可靠性优先，其后经济’的目标，把它放在适用的费用层之后，作为同费用范围内的偏好。保留明确的 legacy 选项复现旧结果，给新规则独立版本标识。
如果某个费用前目标确实承担登记的备用/准备作用，明确记录它的工程理由、代价和适用条件，不把其条件费用最优写成无条件经济最优。
若发现启动计划和实际费用之间存在会影响选择的实质计价问题，先做最小、可归因修正；不能借机引入未来优化或没有实测依据的启动费。费用字段中的微小偏好与实际能源费可以拆分，但保持价格、燃料转换和历史结果可追溯。

若默认目标顺序在全时域改变，需新跑匹配的 N/F/D/FD 受影响完整工况，不能用旧 N 搭配新 F，也不能把仅 90 min 后分叉的续跑冒充完整策略对照。新版本的 0–30 min 轨迹可能改变，必须重新检查故障目标是否真在运。
若新规则使 GT2 原本就不运行，如实标为非活跃目标，不为维持旧叙述强开 GT2。旧 V26 活跃链证据保留；若本轮需要补新的活跃链，只按新正常前缀的实际在运设备预登记一次机械选择规则，形成完整匹配四案并声明这是新工况，不与旧案混算。

工作 A 完成标准：目标顺序与声明一致；每个保留的费用前偏好可解释；同状态证据和实际执行证据齐全；真实物理约束与当前信息限制未削弱。‘GT2 一定重启’不属于完成标准。

实际派生 IDF/天气/求解设置 → 逐盘管 TOTAL cooling service → 实际系统步长积分 → 标准时整点小时 → 8760 Q_c_demand → 分等级服务需求。

若实际年度原文件找不回，本轮仍可完成下面明确标注的条件敏感性，但年度来源资格保留未决。不要伪造重建一致，也不要为了补一个 missing 标签默认重跑全年。只有发现具体、会改变工程结论的来源缺陷，才允许有边界地生成新候选来源；新来源另立版本，不能冒充找回原运行。

5. 工作 C：冷需求对供能结论的有限敏感性
====================

5.1 现成证据
两条正常参考均为 120 h、7 月 18–22 日，没有故障。原设置与 MinPlant=8 设置的八盘管总冷差约 +0.2763%，但标准时 (7 月 20 日 08:00,09:00] 差约 +100.963 kW、+11.28%。原正常曲线与 Min8 诊断均不能据此称为真实观测或修正真值。
本包 evidence/cold_normal_numerical_sensitivity_hourly.csv 给出已独立积分的原值、Min8 值和完整差值序列，使用前核对原始源绑定。

5.2 选择可解释的映射
若工作 B 证明年度与有限参考在时钟、提取和历史状态上可直接对应，按一致定义构造两套冷需求。
若热历史/初始化尚未对齐，可在原年度基线上叠加已测得的逐小时差值，但必须登记为‘有限正常数值差异构造的条件扰动’，不能称作真实误差或修正 8760。这只是回答结论对该幅度、该时序冷需求变化是否敏感。

保留窗口内完整差值时序及正负号，不只拿 +100.963 kW 单个尖峰。若叠加后出现负需求、关键区代理超过总量或无法对应小时，记录为不可映射，不静默裁零或改等级。

关键区分配优先沿用当前有依据的规则，但必须输出每个等级实际如何变化，区分：已有 OR 观测支持的变化、来源恢复后支持的其他区域变化、仍然只是既定分配假设的部分。不得任意把总冷增量全部压给 P0，也不得偷偷全部塞 P3 来维持关键区不变。沿用分配规则也不等于已验证所有关键区的真实负荷敏感性。

如果结论确实取决于未知关键区分配，先准确指出依赖关系；只在这个触发条件满足时，允许对同一正常窗口补两条配对 EnergyPlus 运行，增加必要关键区输出而保持其他设置和 sizing 一致。不能直接外推四个 OR 稳定就代表全院关键区稳定。

5.3 只选少数有用窗口
默认两个窗口以内：
W1：同一 120 h 区间内包含最大小时差、并包含前后必要运行过程的窗口。
W2：同一共同区间内、依据原基线已有记录最接近冷量容量、库存或备用边界的窗口。

如果共同区间没有临界窗口，就说明未覆盖，不强行制造。不要把 7 月的差值搬到其他季节后称作那里的数值误差。窗口长度应覆盖相关准备/释放和初末库存影响；不必为了短而只取一个小时，也不必默认全跑 120 h。

使用 C 和当前研究已登记的主要对照策略，优先两种策略；如果现有主结论确实涉及第三种，记录理由后再补。不能新造一个明显劣化对照，也不能只测试 C 却宣称策略排名稳健。

每个窗口的两套冷需求，配对使用：相同物理模型、设备容量、初始库存、故障序列、非冷需求、天气/可再生、价格、末端规则、控制周期和信息条件。先冻结方案再运行。

固定信息规则，不是强行固定旧冷负荷预测值。各策略对扰动后当前需求应获得同样的可见信息；若原模型本就有合法预测，保持相同预测生成方法、范围和更新条件。不能只变实际冷需求、仍喂旧预测而把试验混成预测误差研究；没有预测器就不新增。

5.4 看工程判断，不只看总能量
逐方案、逐负荷版本报告：
— P0/P1 各载能需求、实际服务、原始 ENS 与工程中断；
— 可用冷量/电量/蒸汽上限是否触发，缺口发生的实际时间；
— 储能最低库存、耗尽时间、柴油燃料/备用边界；
— 设备启动、切换和恢复轨迹是否变化；
— 实际费用、条件 CO2 及初末库存；
— 策略结论是保持、改变、并列或无法判断。

原始求解失败、超时、回退或不可行要单列，不把回退当成与成功求解等价的策略结果。各载能服务与库存继续用原硬约束和原容差验收。各等级冷需求之和必须与总需求吻合。

排名差接近求解精度、已登记等价带或未消除的输入不确定性时，写无法区分，不凭末位数字宣称排名翻转。不能制定‘总冷量差小于 1% 就通过’的替代标准。

5.5 接受三种诚实结果
S：有限条件下稳定。具体窗口、分配假设和容量下，关键服务判断与有意义的策略排序未改变；物理硬约束通过。
D：对扰动敏感。关键失供由无变有、容量/库存判定改变，或有意义的方案排序改变；只对改变结论的窗口补来源证据或修正。
U：暂不能判断。来源/时钟/关键区映射不足，或者求解与差异量级不能区分；保留条件试验，不升级成年度模型已验证。

S 不等于全年或全院实测正确；D 不等于模型必然算错；U 不能被写成通过。不要为了把 D/U 改成 S 而调阈值、容量、事件或分配。

只做有工程含义的测试：

— 两负荷版本/两策略公平比较，费用和库存按实际轨迹对账；
— 不合格温度/动态冷侧默认不参与主结论。

定向验证足以解决风险后停止扩测。若仓库要求终态完整默认测试，完成修改后统一跑一次，保留原始日志；不要每改文案重跑全部。新测试应覆盖真实风险，避免只复述实现或检验写死数值。

满足以下条件即可结束本轮，不必追求‘所有模块全绿’：
1. 目标顺序及每个上层偏好已公开；必要修正已按真实执行验证，未把静态目标下降冒充累计收益。
2. 原年度来源状态清楚，任何新候选/条件扰动都有独立身份，原输入未被静默替换。
3. 已完成限定冷需求敏感性，并明确 S/D/U 及适用边界；有实质敏感性时已针对性处理或准确列出阻塞。
4. 主模型受影响的守恒、库存、启动、服务优先和信息边界通过必要验收。
5. V26 两条失败热支线保持真实状态，没有以放宽门槛或换名方式恢复资格。
